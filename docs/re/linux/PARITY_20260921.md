# Linux 0.6.1.18 integration and test record

Integration worktree: `linux-parity-work`, starting from Linux merge PR #5
(`port/dev`, `7f55411`) with Windows main `f766960` followed by release **v0.6.1.18**
(`a5aeda76ed2927229397fe85619d1d13326e46d5`) merged.
The Windows baseline is integrated with native implementations of the features
listed below. This document records the checks performed and their limits.

## Implemented and checked

- Native dedicated startup, save selection, autosave, pacing, Vulkan render
  suppression, isolated bridge ports, and Linux watchdog/service tooling.
- Native save/load/pause-and-drain controller with process-scoped mailboxes.
  The VPS native game completed an entire direct SyncParticipant recovery:
  hold, save, snapshot verification, epoch reset, load, fingerprint, release.
  Subsequently two actual native processes completed an automatic frozen join
  (operation `dc6fc030a568d8e38c8622bdd084bdc1`) and explicit lobby resync
  (`dd678cd64ef6e65dfa886ca7353db31e`), with matching snapshot digests and
  zero reported desyncs. The v0.6.1.18 pair repeated the frozen join successfully
  (`bd0ab92a486aa691924f508a71026dfc`) and completed a coordinated autosave
  (14,803,866 bytes) after the Lua hold acknowledgement.
- The ordinary lobby launcher now supplies `--sync-runtime-dir`, `--save-dir`
  and `--game-pid`. Recovery controls consume shared runtime events, readiness
  tokens and retry operations. A real solo lobby correctly refused a resync
  without another connected player.
- Save picker and mod advertisement, native Workshop registry plugin,
  catalogue refresh, and in-game lobby opening. A live catalogue refresh
  registered an isolated fixture Workshop mod and returned its receipt token.
- Vehicle reversal layout; native rename/colour origin replay; spare-line
  callback path; platform-assignment tagging and replay context.
- Road ownership capture now appends one `OWNERS` value per added edge.
  Native `optional<PlayerOwned>` uses player at +0x70, engagement byte +0x74;
  padding is ignored. Evidence: `SLICE_CONSTRUCTION.md`, 0x2f74205/0x2f74210.
- General modular-station endpoint adoption, using Linux proposal offsets
  +0x220/+0x270/+0x2a0 and construction +0x778/+0x790. Transactional tests
  cover frozen-index compaction, transferred object vectors, heap and inline
  tag strings, and refusals leaving the proposal untouched.
- Entity-only ownership now implements the Windows player marker and publishes
  `entity_owner_v1=1` only after successful guarded installation. Its generated
  relay runs in an executable ABI fixture. See `ENTITY_OWNER_20260922.md`.
- Entity-window company wash redirects the 14 calls to native bind helper
  0x1444ee0. Native style method 0x30550d0 and the non-asserting ECS owner walk
  are shared with the existing station glyph tint. This new window path still
  needs live foreign-company visual verification.

- Native Steam transport compiles the shared Windows implementation with POSIX
  sockets, Linux callback packing, and the game's already initialized Steam API.
  A real VPS game published its identity and answered the control protocol.
  CTest exercises callback sizes, occupied endpoint ports, actual UDP forwarding,
  the 1,200-byte reliability boundary, close and shutdown. External Steam P2P
  requires another account and has not been exercised with the offline laptop.
- Vehicle RGBA and station-label colors are implemented and pass geometry,
  texture/layer, UV, owner, alignment and grow-path fixtures. See
  `COMPANY_DRAW_20260921.md` for native ABI evidence. Live visual checks remain.
- The Linux lobby package builds with Python 3.12.14 and needs glibc 2.17.
  All five packaged self-tests pass: lobby, relay, mesh, mods and transfer.
  The relay fixture now drains while sending, like the real bridge; its previous
  send-all-first approach overflowed the default Linux UDP receive queue.

The soldier SDK build has passed all 52 CTest cases. New coverage
includes controller ABI fixtures, recovery UI transitions, Workshop catalogue
ownership, road ownership and station connector remapping. The collapsed-panel regression and dedicated autosave hold/failure/timeout
paths are included and passing.

## Live discoveries

- The platform-assignment hook's expected byte array must have static storage:
  registration stores its pointer and installation happens later. Live startup
  caught the temporary-array mistake; refusal correctly blocked multiplayer.
- Panel opening must be polled from `Visible()`, before the compositor decides
  whether to call `Frame()`. Polling only in `Frame()` stranded collapsed panels.
- Native recovery support must be passed through the real lobby launch, not
  just tested by constructing a SyncParticipant directly.
- Frozen joins bypass legacy start handlers: both native and Windows menus
  now publish company configuration with roster changes. Explicit companies
  mode is retained even with one player. The native legacy world-switch path
  now queues the verified in-place loader, retaining manual fallback on refusal.
- The host now clears every member's loading stage after a completed recovery.
  Windows 0.6.1.18 otherwise leaves its transfer progress at 100%, blocking
  company changes. The real lobby/UDP/snapshot fixture covers this without
  relying on a menu to send a stage-clear command.
- The old native ownership patch removed the engine assertion but lacked the
  entity-only extension required by shared Lua. A live company command exposed
  the mismatch; the extension and capability publication are now implemented.

## Cross-platform and packaging checks

A native host and a Windows 0.6.1.18 client under Proton completed automatic
frozen joins, including operation `559e7eee91a578cacecda6b0638d8bb1`. After the
company-config fix they repeated it (`ba0422562d0e0e3aaaf1fb8f142a678e`), reached
live play with companies enabled and zero reported desyncs. Both games also
executed the native-origin and Windows-origin spare-line creation requests.

The `.run` installer passes extraction/checksum, dry-run, wrapper, installation,
upgrade, legacy-loading migration and uninstall-preserves-data checks. The
packaged native release installs and configures through `tpf2server`, including
the Workshop plugin, frozen lobby executable, dedicated flags and private
userdata. The native watchdog passes its three real-process tests, including
not killing an unrelated process and reaping an exited wrapper's remaining child.
The real native game also starts and autoloads through `native_watchdog.py`, the
installed `tpf2mp-launch` wrapper and the game's own `run.sh`.

After the entity-owner fix, operation `92b0d21cbb18d144ad00174f0408f82b`
completed frozen join and cleared all loading stages automatically. A native
`CMNEW` command created company 3 on both platforms; the native host switched
from company 1 to 3 and the Windows peer applied the matching origin mapping.

## Validation limits

Platform-assignment, modular-station welding and the new vehicle/window/label
colors have guarded native implementations and fixture coverage; their full
interactive gameplay/visual checks remain for a desktop test session. External
Steam P2P requires another account. The VPS pair uses UDP and TCP save transfer
because both games use one Steam account. Experimental no-WSI rendering remains
off by default, matching the Windows dedicated-server recommendation.

The production Proton server remains separate from the native test instance.
The requested VPS operating mode after testing is Steam offline. The offline
test laptop was not available during this integration.
