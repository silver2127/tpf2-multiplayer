## Existing gap and Windows change

`bigmap/src/terrain_sidecar_io.h` records a call-start timestamp, then falls
back from an unchanged expected save to exactly one recent `.sav` in its
folder. The scan allows two seconds of timestamp slack, excludes directories
and `.sav.lua`, and rejects zero or multiple candidates. It changes the final
sidecar destination, hashes the selected save, stamps the previously captured
temporary sidecar and renames it. The capture itself is still at SaveGame entry.

Native `bigmap/linux` has no equivalent capture/serve implementation or save-ID
resolver. Its save compression patches are not sidecar hooks. The prior
[terrain ownership gap](DEV_8C3C02A5.md) still applies: Windows PickTerrain uses
alignment/load candidates plus the Windows pager arena and live tile count;
Linux's userfaultfd pager does not establish those world-lifetime contracts.
Merely translating FindFirstFileW into a directory iterator would not implement
this behavior. No disconnected helper or unverified patch was installed.

## Static attempt in this integration

Searched `~/tpf2-re/linux/funcsig.csv` for SaveGame, StandardSaveGameBackend
and GetTileCache; disassembled the actual lab ELF with `objdump -d -Mintel`.
The job's `meta/live/` retains the candidate rows and disassembly, including:

- `SaveGame` at `0xc7ec00`, anchored by the Serializer.cpp signature.
  Entry bytes are `f3 0f 1e fa 55 48 89 e5 41 57 41 56 41 55 41 54 53
  48 81 ec 08 06 00 00`. The prologue loads R12 from `[rbp+0x10]`, EBX
  from `[rbp+0x18]`, and the monitor from `[rbp+0x20]`. Together with the
  signature and subsequent string reads this identifies SaveGameId as the
  seventh explicit argument (entry RSP+8), followed by bool and monitor.
  Unlike the Windows hook, this Linux call has no leading hidden result pointer:
  the six reference arguments use RDI, RSI, RDX, RCX, R8, R9.
- At `0xc7eccd`, `test bl,bl` selects the branch to `0xc7fdd0`. That branch
  loads backend vtable slot `+0x88` at `0xc7fdf4` and calls it at `0xc7fe72`
  (`41 ff d5`). Call setup is RDI=result string, RSI=backend, RDX=by-value
  string storage, ECX=date value, R8=id namespace, R9=rotation vector.
  The result replaces the local save name at `0xc7fe7f`. This is static
  evidence that the engine can replace the ID's name for autosaving.
- The signature identifies `StandardSaveGameBackend::GetAutoSaveName` at
  `0x3342cb0`. Its string construction at `0x3342d3c..0x3342d59` uses the
  eight bytes at `0x3f2d43d`, confirmed by objdump as `autosave`.
  The runtime vtable target has **not** been observed in gdb.
- `StandardSaveGameBackend::GetSavegameInfo` at `0x3341ef0` reads the ID
  through RDX (RDI is the aggregate result and RSI the backend). It reads
  pointer/length pairs at ID+0/+8 and +0x20/+0x28, and resolves an empty
  path using namespace ID+0x40 at `0x3341f52`. Copies use local SSO buffers
  at string+0x10; this is libstdc++ storage, not MSVC's inline union layout.
  This identifies a resolver route but does not prove backend lifetime.

These addresses are research observations only. No new address, structure
layout or byte pattern is used by production code. Existing guarded sites
were checked independently: all 20 and the build-id passed.

`.before-port-60d237c` siblings. Installed this job's soldier libraries,
Big Maps plugin and merged Lua. Used native Big Maps configuration with

No game process, menu, Vulkan device, save operation, breakpoint or gdb
register observation was reached. No Steam/runtime policy was changed.

The unresolved requirements are a live saved-world CTerrain owner, capture
freeze/lifetime and load publication boundaries, verified native grid records
and pager eligibility, backend lifetime/path resolution, and an actual
manual/autosave capture-hash-restore round trip. The timestamp fallback cannot
safely attach terrain until those prerequisites exist. Native sidecars and
this autosave correction therefore remain **not ported**.

Both actor directories were restored, `diff -qr` returned 0 for each, and the
temporary backups were removed. No game was left running and no save changed.
`meta/live/launch.txt` and `restoration.txt` contain this run's evidence;
`actor-logs/` and `actor-data/` are archived actor state and may contain older
runs, not evidence of a successful launch in this integration.
