# Steam Messages Linux integration, dev 1eb30002

Incoming commits: b14f914 and 1eb30002. Neither changes an engine hook,
TransportFever2.exe address, instruction pattern, or game-owned structure.
TCP preference is shared Python. The platform-specific addition is resolution
of SteamNetworkingMessages v002 and the startup mode-switch file.

## Native mapping and evidence

`steam_tunnel.cpp` remains shared, retaining the Linux `std::thread` lifecycle,
shutdown signal, `socklen_t`, `select(maxfd+1)`, CLOEXEC/nonblocking sockets,
FD_SETSIZE protection and existing callback packing. `steam_messages.inl`
uses `dlsym(RTLD_DEFAULT, ...)` on Linux and GetProcAddress on Windows. It does
not load a second Steam library or initialize Steam. Linux uses `access(F_OK)`
on the runtime data directory's `tpf2mp_steam_legacy.txt`.

Read the lab build's ELF notes: build 35924, GNU build-id
`3a0e156390b0e6f1e372051c24802c8493ae454a`. `nm -D` and `objdump -d -M intel`
on its `libsteam_api.so` establish these exports (library-relative addresses,
for evidence only; the implementation resolves names and patches no bytes):

| Export suffix | ELF address | Disassembly |
|---|---|---|
| SteamNetworkingMessages_SteamAPI_v002 | 0x23a60 | ContextInit, returns interface pointer in rax |
| SendMessageToUser | 0x23aa0 | interface in rdi, tail call vtable slot 0 |
| ReceiveMessagesOnChannel | 0x23ab0 | tail call slot +8 |
| AcceptSessionWithUser | 0x23ac0 | tail call slot +0x10 |
| CloseSessionWithUser | 0x23ad0 | tail call slot +0x18 |
| GetSessionConnectionInfo | 0x23af0 | tail call slot +0x28 |

The flat functions use native SysV argument passing; SendMessageToUser takes
interface, identity pointer, data pointer, length, flags, channel in
rdi/rsi/rdx/rcx/r8/r9. No MSVC STL objects cross this boundary. The unmodified
vendored Valve headers select VALVE_CALLBACK_PACK_SMALL on Linux (pack 4).
The compiled adapter test verifies identity size 136 and message release
pointer offset 184. Fields are accessed through those ABI headers, with no
invented game offsets. Received messages remain Steam-owned and are released
through their supplied Release function, including rejected oversized or
invalid-identity messages and pending messages at shutdown.

The chosen callbacks are registered only after the control socket succeeds,
as in the earlier Linux port. Both modes unregister their own callbacks.
Every startup resets the mode, so restarting in Legacy or after an unavailable
Messages accessor cannot inherit a previous Messages selection. Missing
exports or a null accessor disable the transport; there is no silent fallback.

## Validation limits

Fake flat-C exports exercise both complete tunnel modes with real local UDP,
including channel routing, callbacks, reliability flags and clean shutdown.
The adapter fixture covers API errors, receive ownership/bounds and status.
The game launch failed before exec with `bwrap: setting up uid map: Permission
denied`; there was no live API invocation or gdb attachment. No GPU was selected,
no menu appeared and no throughput or cross-platform gameplay was observed.
This exported-API change introduces no unresolved game patch or game-lifetime
contract. Real two-peer Steam validation remains a test limitation.

Static disassembly, ELF notes, launch output and restored-actor confirmation
are archived in this job's `meta/live/`. Copied actor logs may predate this
attempt and are not evidence that this build ran.
