# Material-index measurement probe investigation

Target: `8066c58f6911585a3e7ba908e6c11281f92840c8`. Linux Steam 35924,
GNU build-id `3a0e156390b0e6f1e372051c24802c8493ae454a`, checked against
the lab ELF with readelf and the existing 39-site verifier.

## Windows contract

The new `material_index_probe=1` is off by default. It records only after
successful optimized selection in the existing `material_index_fast` detour
at Windows RVA `0x315f20`; enabling the probe alone does not install that hook.
Empty layers and stock fallback paths do not reach Record. Under a mutex,
rectangles accumulate into 65,536-byte tiles, counting distinct visited pixels.
A completed tile emits signed x/y, FNV-1a hash, two bytes per linear run and
rounded order-0 entropy bytes to `material_probe.txt`, then is erased from the
accumulator. These are measurements, not a sidecar format. Upstream's two-load
hash comparison and size/timing figures are Windows observations only.
Both Windows files remain byte-identical to the incoming commit.

## Fresh static attempt

Re-read DEV_7E3D3BFA, searched the supplied Linux funcsig.csv and disassembled
the actual ELF. Source-signature anchors identify UpdateBoxAsync LoopImpl
`0xcc5cd0` and FinishBox LoopImpl `0xcca8a0`. Full disassemblies are in this
job's `meta/live/material-{worker,finish,finish-worker}.asm`.

- `0xcc5d22`: `e8 c9 e4 ff ff` calls `0xcc41f0`, with RDI pointing to the
  closure, ESI=0 and EDX=1 on this branch. The worker saves RDI/R14,
  ESI/R12D and EDX/EBX, allocates 0x1000 scratch bytes and iterates ranges.
  This is not the Windows nine-argument material-selection ABI.
- `0xcc4300` loads a packed pair through RDX, stored at RBP-0x120 by
  `0xcc430e`; its halves participate in subsequent coordinate subtraction.
  This is a tile-key candidate, not yet a live-proved key.
- `0xcc4393` calls `0xccf100`; its return is saved at RBP-0x1b0, then
  loaded into R10 at `0xcc4687` (`4c 8b 95 50 fe ff ff`). At `0xcc4983`
  (`49 8b 02`) RAX loads through R10; `0xcc498a` (`88 14 08`) writes
  a selected material byte at RAX+RCX. The fallback writes the same address
  at `0xcc4a49`. This identifies an output-access candidate, not its lifetime.
- `0xcc49db` loops back for more layers. `0xcc49e1` restores the saved
  closure to R14; `0xcc49ef..0xcc4a18` advances to another work item.
  A probe must capture after all batches for the rectangle, before reuse,
  and prove coordinate bounds and exclusive access before copying bytes.
- Investigated a later boundary as an alternative to the inlined loop:
  FinishBox's `0xcca900` (`e8 6b 94 ff ff`) calls `0xcc3d70` with RDI
  pointing to a local return object, RSI to the closure, EDX=0, ECX=1.
  `0xcc3da0..0xcc3daf` zero its three pointer slots, consistent with the
  exported vector return and a SysV hidden return pointer. This worker
  calls `0xcc0300` at `0xcc3e97`, moves three local vector pointers at
  `0xcc3eba..0xcc3ed6`, appends through `0xccda30`, and has cleanup calls.
  The exported tuple-of-coordinate-and-byte-vector type alone does not prove
  that these bytes are the same raw 256x256 selection output: texture
  transformation, size and synchronization still need tracing and live proof.

No candidate became a runtime hook, and no Windows address, vector layout or
calling convention was copied into native code. Existing native byte guards
remain unchanged.

## Live attempt and decision

Built candidate soldier libraries and installed them, the Big Maps plugin,
configuration and merged Lua into the backed-up native lab payloads. Requested
`autoload=1` and `newgame_density=0`. Ran only the prescribed lab launcher:

```
tools/sandbox/tpf2mp-lab run native --root ~/.local/share/tpf2mp-lab
```

It exited 1 immediately: `bwrap: setting up uid map: Permission denied`.
No game process, title menu, renderer selection or loaded save was reached;
gdb could not observe any buffer, coordinate or worker lifetime. No desktop
input or Proton peer was used. Both payloads were restored from uniquely named
`.before-port-8066c58f` backups and `diff -qr` returned 0. No save changed.

Leave the native probe unported and stock material selection intact. Next
attempt needs a working lab, worker/rectangle completion breakpoints, output
size and coordinate checks, ownership/concurrency observations, and comparison
of captured tile hashes across two loads. Do not infer native output identity
or compressibility from Windows results. Evidence includes launch output,
restoration checks and actor logs/data snapshots (including historical files).
