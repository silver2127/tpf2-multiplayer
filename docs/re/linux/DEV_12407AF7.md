## UCRT math

Applied `linux_ucrt_libm_parity.patch`. The six import slots are independently
checked by `tools/linux/verify_libm_parity_elf.py` against `.rela.plt`:
`sinf=5a471b8`, `cosf=5a471c8`, `sincosf=5a470c0`, `tanf=5a470d8`,
`acosf=5a472b8`, `atan2f=5a472b0`. They are JUMP_SLOT relocations in RELRO;
DT_FLAGS includes BIND_NOW. Runtime installation verifies resolved symbols
before using the existing self-memory writer. No entity layout is involved.
SysV scalar float arguments/results use XMM0 (atan2f also XMM1);
sincosf's two output pointers use RDI/RSI. Only this executable's slots change.

The export source/assert anchor names CreateAngle2SegMap at `15789c0` in
street_developer_util.cpp. The three calls at `1578b3b`, `1579031`, `157a4ac`
all target double atan2 PLT `6dbc60`, which jumps through import `5a46cb0`.
Disassembly confirms CVTSS2SD on XMM0/XMM1 before each call and CVTSD2SS after
it. The wrapper takes two doubles in XMM0/XMM1, narrows exactly, evaluates the
UCRT float model, and returns the exactly widened float in XMM0.

Extended upstream's guards to include the complete result conversions:
26 bytes at `1578b33`, 24 at `1579029`, 35 at `157a4a4`; exact arrays reside
in `libm_parity_sites_linux.h`. The read-only verifier checks every byte,
call destination and import identity. Unit tests independently corrupt the
last byte of each guard and require refusal before writes. Existing fixture
tests cover foreign imports, wrong build, kill switch, repeat install and GOT
rollback. A redirect failure after GOT installation is reported as partial,
as in the supplied implementation; it is not a successful parity result.

Models compile with `-ffp-contract=off;-fno-fast-math`; explicit FMA remains.
Soldier/GCC passes the supplied Windows golden stride hashes and vectors.
The upstream exhaustive 2^32/2^31 comparisons were NOT rerun here. The model
matches upstream's AVX2/FMA UCRT path; Windows SSE2-path peers can differ.
This is not a claim of complete libm or cross-platform simulation parity.

## Octree

Applied `linux_bigmap_octree_depth13.patch`; full site/ABI account is in
`bigmap/docs/linux/PORT.md`. Independently checked all 29 registered guards
against the lab ELF. Disassembled `16aa040..16aa510` and `13ec500..13ec590`;
function-signature exports independently anchor Resize (`16a6580`) and

The child site at `16aa190` contains the 20-byte LEA/MOVSXD/MOV/LEA/JMP
sequence recorded in `octree_depth.h`; the decoder at `13ec530` contains its
37-byte threshold loop. Root site remains `a84234`. Parent is RAX, child
array RDX, octant R15D, running ID R13D, remaining depth R9D. Replacement
keeps the original continuation/register contract. Native assembly fixtures
exercise the emitted stubs, including invalid-ID SIGILL paths.

Unicorn executes the original ELF descent/decoder with the exact new stubs:
1,620 depth-13 nodes and 1,462 depth-12 nodes, unique positive IDs, correct

also reproduces the original overflow. This is emulation, not live gameplay.
Fixed an upstream implementation/documentation discrepancy: `octree=0` now
ignores invalid `octree_depth` values, with regressions for 0/10/14/99.

## Target-set performance

The hot wrappers use a linked list of private TargetRecords, not an order
vector. Windows set order already has a bucket structure. Added a 1024-bucket
multiplicative-hash index for target -> TargetRecord inside each owner. Insert
and erase search only the selected collision chain. A doubly linked list
preserves existing reader iteration and permits constant-time record unlink.
The index costs 8 KiB per owner, plus two pointers per target record. No new
per-operation index allocation; record/set allocations remain unchanged.

All engine hooks, guards, owner binding/destruction, negative-target behavior,
mutex scope, native-node validation and Windows insertion/erase history are
unchanged. The index is private storage; it introduces no game offsets or
new lifetime inference. Regression exercises 4,096 targets (collisions),
erase/reinsert, complete deletion/recreation, traversal and owner cleanup;
existing Windows-oracle, exception, register and threaded fixtures still pass.
Native-set scans, reader scans, allocation churn and mutex cost remain. No
live speedup or recovery of the reported 20% is claimed.
