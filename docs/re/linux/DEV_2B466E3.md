# Native sites for Windows dev 2b466e3 (0.6.1.20)

Binary: Steam Linux build 35924, GNU build-id
`3a0e156390b0e6f1e372051c24802c8493ae454a`. Addresses below are ELF virtual
addresses, added to the runtime PIE base. Verified against the lab's actual ELF
with objdump/readelf and `tools/linux/verify_dev_2b466e3_elf.py`.

## Vehicle stop/go

The existing factory registry already identifies `0x15ebf00`, tag 8, with the
14-byte P14A guard. `funcsig.csv` and the assertion string at `0x4326a00`
identify `Command make_cmd::SetUserStopped(const ecs::Engine&, ecs::Entity, bool)`.
The fresh disassembly establishes the SysV contract without borrowing Windows
registers or layouts:

| Site | Instruction / meaning |
|---|---|
| `15ebf00` | `f3 0f 1e fa 55 48 89 e5 41 57 41 56 41 55`: checked entry |
| `15ebf37` | `mov ebx,edx`: entity is edx |
| `15ebf39` | `mov r12,rdi`: hidden Command result |
| `15ebf3c` | `mov r14,rsi`: engine reference |
| `15ebf4f` | `mov r15d,ecx`: stopped boolean |
| `15ebf65` | entity stored at temporary payload +0 |
| `15ebf75` | `mov [rbp-0xd8c],r15b`: boolean at payload +4 |
| `15ebf7c` | `mov byte [rbp-0x48],8`: command variant tag |

The vehicle toggle's two factory returns are `1431102` and `1431204`.
The first passes ecx=0, the second ecx=1. Both pass edx from the entity field
and rsi from the engine, then the same Command slot to Add. Add returns at
`1431129` / `143122b`. Their already registered guarded windows
`[14310fd,1431129)` and `[14311ff,143122b)` hash to `d80de86f` and `27d7f59d`
(FNV-1a 32). The verifier checks both full windows and their two direct calls.
The new area handler emits `ARMED 1\nVSTOP <edx> <ecx&1>\n`, arms cancellation
with no callback, and leaves script replays untouched. Core build, prologue,
window, Command pointer/tag and Connection-constructor guards still apply.
No new ECS component offset or lifetime assumption is introduced.

## Empty cancelled Add result: already implemented

`slice_install.cpp` already calls the actual empty Connection constructor,
`3190240`, after cancellation; its entire 51-byte body is verified before Add
is hooked. Fresh disassembly confirms `mov edi,0x10; call 6dbce0` (operator
new), zero stores at allocation +0 and +8, then stores that allocation into
the caller's return slot. The copy at `31902c0` dereferences the source's
allocation without a null check. This is precisely the contract the Windows
fix establishes. Writing null, or using a Windows allocator RVA, would regress
Linux. Existing cancellation tests cover constructor invocation and mismatches.
See [SLICE_CORE](SLICE_CORE.md), C-ADD-10, for the original ABI and ownership proof.

## OpenGL presentation

`objdump -R` identifies `5a47c38` as the SDL_GL_SwapWindow JUMP_SLOT.
PLT `6ddb70` is `ff 25 c2 a0 36 05`, targeting that slot. A whole-text objdump
search finds one call, at `3496531`: `e8 3a 76 24 fd`.
Its enclosing function starts at `3496500` in the OpenGLRenderContext block;
`349651b: mov rdi,[rdi+0xd8]` supplies the SDL window. The typed redirect takes
that SDL_Window pointer in rdi and forwards it unchanged to the original PLT.
No code reads the renderer's +0xd8 field itself.

`OverlayGlInstall` verifies the PLT bytes and the exact call destination before
redirecting through the existing near-stub writer. The menu's existing build-id
gate applies first. A mismatch leaves OpenGL untouched. SDL resolves the GL
functions with a current context; all are required before drawing. The shared
Windows blitter now has a Linux resolver, retaining Windows resolution and
calling conventions under `_WIN32`. Context changes reset per-thread GL state.
The CPU panel is composited to opaque BGRA, blitted before swap, with framebuffer,
texture, PBO, unpack, scissor and sRGB state restored. Input uses the GL drawable
size for GL windows. The existing Vulkan path is retained. Native lobby/load
polling already runs independently of Vulkan presentation.

`tools/linux/test_gl_overlay.py` runs the upstream pixel/state tests using a real
hidden SDL GL context: placement, vertical orientation, padded pitch, unchanged
outside pixels, all modified GL state, cached blits and replacement uploads pass.
This is an actual GL test, **not** observation of the game renderer.

## Steam UGC ABI

The merged shared tunnel resolves the flat C exports for ISteamUGC v016 through
its existing Linux dlsym resolver. No game patch or C++ interface vtable is used.
Subscription call handles and item IDs are uint64; download state/size arguments
match the upstream flat API, compiled with SysV on Linux. Existing Linux packed
P2P callback layouts, socket lengths, select nfds, thread lifecycle and identity
paths remain. The native fake-export/real-UDP test additionally exercises UGC
subscription, download state, paths with spaces and unavailable-interface fallback.

## Live attempt and remaining evidence

The native actor's libraries/mod and userdata were backed up. The new libraries
and Lua were installed only there, with a 1280x720 window and OPENGL selected.
The standard lab command failed before exec: `bwrap: setting up uid map:
Permission denied`. The fallback documented in [DEV_D6DB920F](DEV_D6DB920F.md)
used `/usr/bin/bwrap` with all original outer lab mounts, bypassing only nested
pressure-vessel. The game exited 53 during Steam initialization:
`SteamAPI_IsSteamRunning() did not locate a running instance of Steam`.
A /proc comm scan found no Steam process. Steam was not started or modified.

No title menu, GPU selection, world, vehicle UI or gdb probe was reached. Thus
there is no new live game register capture or visual/cross-peer claim. Static
contracts above and fixture tests passed; in-game smoke tests remain outstanding.
The actor's full backed-up libraries, Lua and userdata were restored, with no
game left running. Launch transcripts, process scan, test logs and a restoration
note are in the job's `meta/live/`; copied actor logs also contain older runs and
are explicitly not evidence for this integration.
