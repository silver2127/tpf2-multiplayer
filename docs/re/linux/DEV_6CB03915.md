## Road space: retain the Linux walk and collect its terms

Disassembled `0x2e55630..0x2e56700`, anchored by EdgeUseManager.cpp and the
GetEdgeDataPtr assertion. The signature text is at `0x4e59e60`, source path at
`0x3ec3860`, assertion `datas[edgeId.index].length > .0f` at `0x3ec3920`.
The plain sum is `0x2e557d0..0x2e55b2e`; the predicate overload is
`0x2e55b30..0x2e563ff`. These match the Windows clipped-footprint loops,
including forward/backward cases and 20-byte entry advances. GCC inlines
GetEdgeDataPtr and GetPos; a Windows helper address cannot be substituted.

Initial layout investigation found manager indices at +30, edge groups at +48
with 72-byte stride, 32-byte edge data, and entries at edge+8. MovePath lookup
uses manager+18, 136-byte components, path index +34 and position +38;
complemented negative indices use manager+20, 96-byte components and +18/+1c.
Both have 32-slot pages. The final implementation does **not** reproduce these
layouts or call guessed helpers: the original ELF performs every lookup,
assertion, clipping operation and predicate invocation.

Filtered predicate evidence: `2e55c93` tests its libstdc++ manager pointer at
+10; `2e55ca3..2e55cad` passes rdi=predicate, rsi=entry, rdx=float reference
and calls the invoker at +18. There is a second invoker call at `2e55f0f`.
Neither is intercepted or reissued. The original empty-function throw remains.

Each entry wrapper supplies a stack accumulator and links it into thread-local
storage. Each sum relay appends one already-rounded float and then performs the
original instructions. At return, the shared `roadspace.h` sorts the terms and
sums in double. More than 512 terms returns the original engine result, already
computed by the same walk. Nested calls get separate accumulators; cleanup on
unwind restores the previous context. No engine-owned vector is modified, no
predicate is called twice, and no per-vehicle guarded-read syscalls are needed.

Both bodies have rsp aligned to 16 at these sites (plain pushed rbp; filtered
pushed rbp plus five registers and subtracted 28 hex). Relays save nine
caller-saved integer registers, flags and all 16 XMM registers (336 bytes),
call the noexcept term collector with xmm0, restore them, and execute the
stolen instructions. Plain cmp recreates the flags for the following branch.
The plain body has no red-zone locals that those saves overwrite. No Windows
shadow space or nonvolatile-XMM assumption is used.

`movement_checks.h` pins the **entire** plain and filtered bodies, including
all layout and predicate accesses. `verify_movement_elf.py` decodes both bodies,
checks all patch boundaries and rejects branches into stolen interiors. It
also confirms the two filtered local-sum additions and both plain sum bytes.
`roadspace=0` disables both overloads. A failed guard/installation leaves
multiplayer readiness false; the existing build-id and no-patches gates precede
installation.

## Ship / aircraft diagnostics

Source signature exports identify ShipMoveSystem::Update2 at `0x16d75c0`
(20378 bytes) and AircraftMoveSystem::Update2 at `0x16692e0` (26895 bytes).
Disassembled both entries and node loops. SysV rdi=self, rsi=world, edx=count,
xmm0=dt. Ship saves them at `16d75ca`, `16d75e2`, `16d75e9`, `16d75ef`;
aircraft at `1669302`, `16692ea`, `1669309`, `166930f`.

Both steal only `f3 0f 1e fa 55 48 89 e5` (8 bytes), then use the existing
POSIX trampoline. C++ wrappers observe and pass all four arguments to the
original. At `16d78ce` ship increments its record offset by 14 hex; at
`16d78e7` it reloads self+8 and follows the vector. Aircraft increments its
record offset by 14 hex at `1669649` and reloads the holder at `166967c`.
Entity IDs are at the start of each 20-byte family record. The guarded vector
length must equal count*20. None of that storage is rearranged.

Name lookup reuses [TRAIN_ORDER.md](TRAIN_ORDER.md)'s tested Linux reader:
world+48 registry, +80 pools, +98 entity slots, 32-byte libstdc++ Name strings.
The relevant accessor/layout byte checks and relocated Name RTTI text are
verified independently of trainorder=0. Private thread-local buffers hold names,
records and the ranked indices. Logs carry n/named, nameHash, rankHash, idHash
and hypothetical reordered status at most every five seconds per thread/channel.
An unreadable shape skips that observation. `shiporder=0` / `airorder=0` leave
the respective engine function alone. As upstream, these are diagnostics,
**not** ship/aircraft arbitration fixes.

## Shared stations

The LineEditor.cpp signature anchors AddStationInputComponentChecker::IsValidInput
at `0x10bf930`. Its call at `0x10c02c9` identifies the StationFilter body
`0x10c02a0..0x10c03f4`. It extracts the returned classification/entity pair
from rax. Classes 0/1 enter the owner path at `10c0310`; other classifications
skip it. The owner path uses PlayerOwned RTTI at `5a01c18`, type lookup
`9e3d50`, slot lookup `9e5590`, world pools+80, and four-byte owner components.
Missing/negative owners accept at `10c03d0`.

The final gate is `10c03c0`: `39 43 28 0f 94 c0 0f b6 c0`
(cmp [rbx+28],eax; sete al; movzx eax,al). rbx is the filter, eax the owner.
Nine bytes (three whole instructions) are replaced with a
near JMP; resume `10c03c9` is the existing epilogue jump. The relay calls the
helper with edi=owner, esi=[rbx+28], returning an int in eax. The remaining
code reloads rcx before checking the stack canary; caller-saved registers are
dead. rsp is already 16-aligned. Callee-saved registers remain untouched.
The full 340-byte filter body is guarded, and branch-interior checks pass.

The helper permits equality, or companies mode from mp_company_cfg.txt with
the upstream two-second cache. This changes only the line editor's valid-stop
filter, not ownership, demolition, depot eligibility or simulation commands.
`sharedstations=0` leaves the gate unchanged. Wider company-operation gaps
from older integrations remain separate.

## Vanilla load observer and remaining recovery gap

Fresh disassembly of `113f450..113f560` confirms CMenuUI::StartSavegame:
rdi=menu, rsi=LoadGameParams reference, rdx=SavegameInfo reference. It saves
rdx at `113f468`, tests menu+5e8 at `113f47e`, and accesses parameter strings
at `113f48d`/+f8 and `113f49b`/+118 (length fields of the strings at +f0/+110).
Existing [MENU_GAME.md](MENU_GAME.md) AL evidence and the parameter constructor
establish the save-name string at +0, pointer+0 and length+8, 32 bytes total.
The existing G_AUTOLOAD table already verifies its exact first 16 bytes:
`f3 0f 1e fa 55 48 89 e5 41 57 41 56 41 55 41 54`.
Those are relocation-free whole instructions and now form the observer's
trampoline. No other Linux hook owns this entry.

Only accepted loads are queued, with a copied basename and current lobby
generation. The existing thread-local autoload guard suppresses our own loads.
The lobby thread shares the named save, marks the next world token as ours,
and suppresses the host's return start event. No engine operation runs on the
lobby thread. Token polling handles unnamed/generated worlds and invalidates
old snapshot reuse; foreign PIDs are ignored. In-game clients place the new
transfer and get a manual LOAD GAME instruction, consuming saveReady once.
Title-menu clients use the existing verified autoload path.

**Attempted but not implemented:** automatic client in-place loading and the
native pause/drain/save/load/action-hold controller needed for a6af077's
host-keeps-world recovery. Re-examined the full prior save design, this load
entry and the actual SaveGame `c7ec00..c7ec90` / AutoSave completion
`1019f40..1019fc0` bodies. SaveGame takes the seventh SysV argument from rbp+10;
completion loads the result via rdx at `1019f52`, bool via rsi at `1019f55`,
and clears the CGameUI+ae8 saving flag at `1019f8a`. These do not prove which
live CMenuUI remains valid across an in-world destruction, command-thread
quiescence, operation-specific completion ownership, or action suppression
through the transition. The existing title-menu autoload intentionally refuses
when menu+4c8 says a game is running. Calling the same entry from the lobby
thread would bypass those unresolved lifetime/thread requirements. No such
call or false supported-controller status was added. Python/Lua recovery
changes are merged, but Linux native automatic recovery remains unsupported.
