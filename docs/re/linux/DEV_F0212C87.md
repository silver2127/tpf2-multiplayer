## Imported Linux hooks: independently checked against the ELF

`tools/linux/verify_save_steam_elf.py <TransportFever2>` verifies the build-id,
all five whole-function byte guards from the C++ source, and all seven rel32
call targets. `objdump -d -Mintel` independently shows these instructions.

| Function / contract | Guarded address and size | Redirected calls |
|---|---|---|
| boost zstd destructor | `0x3563210`, 67 bytes | `0x3563223` -> `0x3d88c20` (free) |
| boost deflate | `0x3563340`, 162 bytes | `0x3563379` -> `0x3d8d940` (compress), `0x3563399` -> `0x3d8dbd0` (flush), `0x35633d8` -> `0x3d8dc20` (end) |
| boost reset | `0x3563470`, 108 bytes | `0x35634ce` -> `0x3d8acb0` (init) |
| boost do_init | `0x35634e0`, 98 bytes | `0x356351d` -> `0x3d8acb0` (init) |
| Steam poll thread loop | `0x36b1960`, 189 bytes | `0x36b1990` -> `0x36be010` |

The save calls follow SysV: compression context in RDI, output buffer in RSI,
input buffer in RDX; init gets context in RDI and level in ESI. The deflate
function obtains context at object +0, input at +0x10 and output at +0x18.
It branches on its action to flush/end, repeatedly calling compress before end.
The incoming `Streams` adapter preserves this drain loop, including suppressing
empty continue calls while a multithreaded end is pending. The embedded context
remains owned/freed by the game; the adapter separately owns its libzstd context.
No Windows CRT object layout is used here. The real host libzstd 1.5.7 round-trip
fixture compressed 25,165,824 bytes to 9,894,603 bytes with four workers and
successfully decompressed them. This is not a game save/load observation.

The installer previously could redirect the first init but fail the second and
still take over streams despite reporting failure. A release/acquire atomic gate
now enables takeover only after all six redirects succeed. Partial installations
forward init to the embedded API; the other wrappers have no adopted streams and
pass through. The installer fixture covers guard refusal and all six failure
boundaries, including five successful redirects. It uses a fake available zstd
API because soldier's optional system library need not support workers.

The poll loop loads its object through `[rbx+8]`, then `[object+8]` into RDI;
byte +0x130 selects busy versus the existing 200,000,000 ns nanosleep path.
Byte +0x200 exits the loop. `0x36b1995` calls SteamAPI_RunCallbacks after the
redirected poll call. The hook keeps that order and the same thread/object,
adding a monotonic 2 ms minimum interval. The complete loop bytes are guarded;
no guessed call target or new object dereference is introduced by this port.
Live thread scheduling and actual saving remain unmeasured locally.

Road batching keeps the already documented Name/ecs layout from
[TRAIN_ORDER.md](TRAIN_ORDER.md) and [SLICE_CORE.md](SLICE_CORE.md).
The merge retains both inaccessible-tail/4096-pair tests and upstream's paged,
flat, missing and multi-batch name equivalence tests. No new engine patch address
is introduced by the name batching or terrain zero-copy changes.
The existing descriptor checker still verifies the five dispatcher stores and
40-byte Linux guard; the renamed shared recycler does not change their addresses.
Big Maps' checker passes all 30 existing native patch sites.

## Attempt: Sandbox CreateTowns

The existing native factory table calls tag 0x11 at `0x15ee340` an unknown tag.
The shared CmdData variant signatures in `funcsig.csv` place CreateTowns after
RemoveField and before RemoveTown. Scanning ELF `.text` rel32 calls to that
factory finds `0xec054c`, `0x102fbcd` and `0x1977623`; the function export places
these in `0xebfe70` (2384 bytes), `0x102f720` (1784 bytes), and `0x1977430`
(4591 bytes). This gives UI and scripting candidates, not a proved caller filter.

Actual factory disassembly confirms RSI points to a three-pointer vector; it
moves its begin/end out and zeros all three source pointers. RDI is preserved
as the return-object destination; EDX is saved separately. The element copy
constructs a libstdc++ string from pointer +0 and length +8, copies +0x20/+0x28/
+0x30, walks three integer vectors from +0x38 in 0x18-byte steps, and advances
by 0x90. It also reads a byte at +0x80 and floats at +0x84/+0x88. These latter
fields cannot simply be declared uninitialized because Windows notes say so.
At `0xec054c`, RSI is `rbp-0x390`, RDI is `rbp-0x350` (addresses of
stack objects), EDX is 1; afterward
`0x15da840` receives the command and callback-related stack objects.

Still missing: a live town-tool breakpoint proving which caller is the click,
the source TownInfo values and trailing fields, and cancellation/callback
ownership (including clearing the tool's progress bar). The lab namespace
failure prevented all of these. No native capture/cancel hook is enabled on
this static evidence alone. Shared TOWNC parsing/replay is retained and tested
with Lua 5.2; it does not establish cross-platform town determinism. RemoveTown's
new Windows diagnostic probe also has no corresponding new native probe.

## Attempt: minimap climate and M key

The base native minimap was already absent; see [DEV_8C3C02A5.md](DEV_8C3C02A5.md).
Revisited its raw-pixel ImageView candidate `0x30b26c0` with objdump. This does
not establish Lua placeholder interception or texture ownership. Consequently
the incoming minimap script, disk style and icon are retained as Windows assets
but not installed as an operational native minimap.

`funcsig.csv` anchors CreateConstructionMenu at `0x1046540` via
`GameUI_menu.cpp`. Disassembly at `0x1046582` loads `[RDI+0x448]`, then at
`0x1046590` loads +0x148 (different from Windows +0x150), then +0x10 into RCX.
`0x10465f1` takes RCX+0x938, consistent with the climate-id path. The Linux
libstdc++ string layout differs from Windows; the climate repository entry,
PreviewColoring variant layout and world/UI lifetime still need proof.

For keyboard focus, the source signature identifies `UI::SetGlobalCore` at
`0x3075310`; `0x3075329` stores RDI to `0x5b360b8` with bytes
`48 89 3d 88 0d ac 02`. `CTextInputField::StopEditingMode` is `0x3116dc0`
(`TextInputField.cpp`); `0x3116df5` clears byte +0x72c with bytes
`c6 87 2c 07 00 00 00`, different from Windows +0x74c. These are candidates,
not installed patch sites. The native focused-widget/parent/root/visibility
walk, vtable identity, SDL event ownership and interaction with menu input
hooks remain unproved live. Consuming M before there is a functioning native
minimap would remove the stock action without providing its replacement.
No M-key interception or climate-memory reader is enabled.
