# Per-iteration ECS family ordering (dev 0115785c)

Build 35924, GNU build-id `3a0e156390b0e6f1e372051c24802c8493ae454a`.
Evidence below was obtained from the lab's actual native ELF with objdump,
its exported xrefs, and the ELF verifier. There is **no loaded-game evidence**
from this job. The implementation remains behind `TPF2MP_ORDER_CANON=1`,
with the earlier canonical-order hooks; default activation is not ported.

## Iteration boundary and ABI

Windows patches Engine::Update at `0x23e1850`, RCX engine, XMM1 dt.
Linux Engine::GetNodeList `0x3251500` is anchored by the exported signature,
`ecs/Engine.cpp`, and `it != m_familyType2family.end()` assertion. The next
function, `0x32515b0`, walks the engine's systems, calls that GetNodeList,
then invokes each system's update vslot `+0x58` with RDI system, RSI engine,
RDX node list and XMM0 dt. Its caller at `0xa617e8` is inside GameSim::Step's
iteration loop: load RDI from `[[GameSim+8]+0x28]`, XMM0 from the saved dt,
call Update, increment the iteration counter at `0xa6180f`, loop through
`0xa61740`. Sorting once per outer Step would be wrong during catch-up.

The native hook is at `0x32515c5`, just after the stack-only prologue, before
any system executes. RDI still holds the engine; XMM0 holds float dt. Guard:

```
4c 8b 67 30 4c 8b 77 38 f3 0f 11 45 bc 64 48 8b
```

Eight stolen bytes are the complete `mov r12,[rdi+0x30]` and
`mov r14,[rdi+0x38]`. Both are position independent. The existing relay
preserves all GP registers, flags, XMM0–15, MXCSR and stack alignment;
its trampoline replays both loads and resumes at `0x32515cd`. ELF checks
verify instruction boundaries and absence of branches into displaced bytes.
The installer checks all seven sites before patching and rolls back on failure.

## Family and node layout

- GetNodeList at `0x325150a` forms engine+`0x160`; its hash lookup returns a
  predecessor, dereferences its next node and reads IFamily* at node+`0x10`.
  `0x325157d` dispatches vtable+`0x10` (SysV slot 2).
- AddFamily `0x3253290` is anchored by its signature and the family-uniqueness
  assertion. At `0x3253382` it allocates 24 bytes, initializes next at +0,
  type_info* at +8 and family at +16. It inserts into engine+`0x160` using
  `0x325b040`; that function links through map+`0x10` at `0x325b100` and
  increments map+`0x18` at `0x325b0d0`. Thus head is engine+`0x170` and count
  engine+`0x178`. This is libstdc++'s singly linked table, not an MSVC ring.
- Recognized getter `0xa914c0`: `f3 0f 1e fa 48 8d 47 08 c3`, returns
  family+8. No-list getter `0xa914e0`: `f3 0f 1e fa 31 c0 c3`, returns null.
  Both byte strings are checked at installation. Unknown getters are refused;
  no foreign virtual function is called by the canonicalizer.
  **Correction (2026-09-23):** these are only the PersonCapacity and
  VehicleOrder copies. GCC emits one getter per family (28 + 35 in this
  build), so this check left 27 of 28 node lists unsorted in production
  (`lists=1 ... unknown/refused=61`). The canon now uses the complete
  inventory in `family_getters_linux.h`; see HOTJOIN_ORDER.md, "Native: GCC
  keeps one GetNodeList per family".
- NodeList vtable address points are `0x59ac260 + 0x20*(N-1)`, N=1..5.
  RTTI at vptr-8 names type_info at `0x5a032e0 + 0x18*(N-1)`; its name
  points to `0x3f9ee60 + 0x20*(N-1)`, `N3ecs8NodeListILiNEEE` (N substituted).
  The verifier checks all five actual names and pointers.
- NodeList+8/+16/+24 is its vector, stride `4+4*N`, entity first, component
  indices following. NodeList+`0x20` is the phmap index: ctrl, slots, size,
  capacity at +`0x20/+0x28/+0x30/+0x38`. Slots contain int32 entity, int32
  position. Remove<1> `0xba1f00` forms list+`0x20`, reads size at `0xba1f9e`,
  computes node count with an eight-byte stride at `0xba1ff9`, updates the
  moved node's index at `0xba2080`, and copies its entire node at `0xba2088`.
  Lookup `0xb9e730` reads ctrl at map+0, slots at map+8 (`0xb9e7b1`), capacity
  at map+24, and addresses an eight-byte slot (`0xb9e7c6`). Remove<2..5>
  are `0xba1ce0`, `0xb9e860`, `0xba1aa0`, `0xba2220`, anchored by NodeList.h,
  their NUM signatures and `itRemove`/`itMove` assertions.

`family_canon_linux.inl` walks the validated chain, recognizes these layouts,
and invokes the unchanged shared `family_canon.h`. It snapshots readable and
writable mappings each iteration, validates vector/slot ranges before direct
access, rejects malformed chains before any list changes, and catches allocation
exceptions at the C++ boundary. Scratch storage is thread local; no engine/list
pointer survives an invocation. Reorders, refusals and average/max microseconds
are logged. Mapping checks do not prove object lifetime or synchronization.
The cost of reading `/proc/self/maps` per iteration has not been measured in-game.

## Fixture and live evidence

`order_canon` executes all seven installed shims with live GP/XMM/flags/MXCSR,
both stack alignments, corrupt guards and installation rollback. Synthetic
Linux families cover all five widths, component payload preservation, index
repair, sorted repeat, cyclic chains, invalid indices, inaccessible vectors
and vtables, read-only ranges and address overflow. `family_canon` runs the
upstream shared algorithm's randomized history and refusal tests.

Both the initial and final-build lab launches failed at uid-map setup. The
previously documented fallback used `/usr/bin/bwrap`, preserving all outer
lab mounts and bypassing nested pressure-vessel. Both exited 53 at Steam
initialization. RADV was requested and the window set to 1280x720, but no GPU
selection, title menu or world was reached. No gdb attachment or XTEST input
occurred. A process scan found no running Steam client. Steam was not manually
launched. The final game's restart helper nevertheless spawned a Steam bootstrap
and missing-libGL error dialog inside the read-only lab namespace; only those
test-created shells/dialog were terminated, with no further game launch.

Libraries, Lua and userdata were backed up to `.before-port-011578`, then restored
and compared by SHA-256 and symlink target. Existing `.before-port` backups were
preserved. Evidence is in the job's `meta/live/`: `family-disassembly.log`,
`addfamily-disassembly.txt`, `map-insert-disassembly.txt`, `canon-elf.log`,
launch logs, fallback script, process scans, `bootstrap-cleanup.txt` and
`restored.json`. Copied actor logs include older runs, not proof for this change.

Still required before default activation: gdb at this boundary in a loaded
world showing both engine instances, the actual getter inventory and every
index/node contract; proof no concurrent consumer retains positions across
this boundary; remove/add and save/reload probes after reordering; cost
measurements; retained-host versus freshly loaded Windows/native comparison
past town growth. Earlier idle-list and capacity-map lifetime gaps also remain.
