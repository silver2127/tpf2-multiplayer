## Seed contracts

The existing Windows FNV-1a/hash-combine helpers supply the arithmetic. Time-only
seeds invert native identity-hash arithmetic modulo 2^32 before applying MSVC's
four-byte integer hash. Mixed seeds invert the full native intermediate, retaining
signed entity input bits. No MSVC object layout is transplanted.

| Native hook | Stolen bytes | Contract |
|---|---|---|
| `16e4987` | `48 89 85 40 ec ff ff` | SimBuilding: hash EAX, store native std-MT seed at RBP-13c0 |
| `16d2e39` | `89 95 00 f6 ff ff` | Runway tag 11: replace EDX seed |
| `172e21e` | `89 95 00 f6 ff ff` | StockList tag 12: replace EDX seed |
| `16f6126` | `89 95 00 f6 ff ff` | Terminal tag 13: replace EDX seed |
| `16ede8a` | `89 95 00 f6 ff ff` | Cargo tag 16: mixed RAX, entity bits through saved RDX pointer at RBP-b48 |
| `16ed2d8` | `89 95 00 f6 ff ff` | Cargo tag 17: mixed RAX, entity bits at R13 |
| `16ed6b0` | `ba 01 00 00 00` | Cargo-terminal tag 18: first combine RCX; entity bits at R14; subsequent XOR completes seed |
| `154a5fd` | `89 c2 89 85 00 f6 ff ff` | Parcel command: hash EAX before EDX copy and store |

For tag 16, function `16edd30` stores its SysV third argument RDX at RBP-b48
(`16edd5f`); `16ede4b/16ede61` loads that pointer and its signed 32-bit value.
For tag 17, `16ed238` copies RDX to R13 and `16ed298` reads signed `[R13]`.
For tag 18 the guarded context reads signed `[R14]`. Thus the hooks reuse the
same seed input read by native instructions, rather than looking up an unrelated
component. The semantic identity of these callback arguments was not observed
live. All GP/XMM registers and flags are saved around the SysV C++ dispatcher;
trampolines replay the original stores. Fixtures execute every seed hook against
64 upstream oracle cases, including signed boundaries.

## Engine and distribution contracts

| Native sites | Contract |
|---|---|
| `14ed9e0`, `db1290`, `14e8ee0`, `d25730` | SysV RDI distribution, RSI engine, RDX bounds; MSVC rejection/modulo mapping |
| `14edc70`, `14ede20` | RDI begin, RSI end, RDX boost engine; forward Fisher-Yates on 8-/4-byte elements |
| `182ac9d`, `182cdc6`, `18296a0` | Bind MT sidecar using `[R12]*31+7`, engine address RBP-248; float helper receives engine in RDI |
| `c45010`, `c46c90` | Capture name seed ECX; substitute MT shuffle only for return address c450f8 |
| `2eccc54..2eccc87` | RCX minstd draw: float(g)-1 then multiply by 2^-31; retain RDX=g-1, XMM2=0 |
| `31b5f7e`, `31b7759` | Remove two-byte endpoint clamp branches (`73 28`, `73 5d`) |

Boost MT uses 32-bit words and index at +9c0; GNU std-MT uses 64-bit words
and index at +1380. The replacement calls the game's guarded raw helpers rather
than imposing a Windows engine layout. Transformator sidecars are thread local;
the native frame is not enlarged or overwritten with a Windows engine.
`182a707` captures the third argument in R12; both seed contexts reload `[R12]`.
The verified draw sites pass RBP-248 directly or through R12. Rebinding reseeds
that slot each invocation. Reentrancy/sidecar lifetime and branch-order parity
remain live-validation limits, not established by the synthetic fixtures.

AirConnectParts has an old branch `2eccd51 -> 2eccc6a` into the rewritten range.
Its unsigned-conversion tail starts at 2eccd38; its only direct entry is the
`js` at 2eccc5b, which the rewrite removes. A preceding unconditional jump at
2eccd2e prevents fallthrough. The verifier explicitly checks these facts.
Float constants at 3e8bdc8 and 3e8beac are verified as 1.0 and 2^-31.

## Installation and rollback

Both modules default on, with `TPF2MP_SIM_SEED=0` and
`TPF2MP_ENGINE_PARITY=0` kill switches. Each checks its complete guarded contexts
and build-id before writing any site. The boot wiring retains all prior modules.

Review found that the supplied engine installer restored earlier successful
hooks but omitted the currently failing hook, even though `InstallHook` can fail
after a write. Include that target in rollback. A regression injects a changed
first byte followed by failure at each of eleven hook sites, checks all original
contexts are restored, and verifies readiness/active-mask remain clear.
