# Native terrain stream and save candidates: dev 9602a389

The incoming Windows commit also supplies a native implementation. It reuses
all existing sidecar hooks; no PE address, MSVC object layout, new ELF site or
new calling convention was introduced. The hook-publication and activation
guards from [the original port](DEV_2B4FD093.md) are retained, as is unsigned
publication-version arithmetic and [two-version retention](DEV_5B817EFB.md).

## Static evidence

Fresh verification against the lab's Steam build 35924 ELF passes build-id
`3a0e156390b0e6f1e372051c24802c8493ae454a` and all 39 entries in
`bigmap/linux/sites.json`. Runtime checks still precede patches and hook
activation. This job's `meta/live/` contains `verify-game.txt`, `addtile.asm`,
`publication.asm` and `alignment.asm`.

- `0xcf73f2` (`49 8b 77 18`) reads CTerrain+0x18. The following coordinate
  calculation uses grid+8 as row width; `0xcf740d` reads records at grid+0x10.
  Two LEAs multiply the index by 40. These are the same grid fields used by
  the new guarded candidate scan, not a Windows structure substituted on Linux.
- `0xcf75ff` (`4d 8b 6c 24 08`) reads record+8 as the vector pointer;
  `0xcf7604/0xcf7608` read end/start, then subtract and divide by two. The
  preceding shared_ptr refcount test and COW branch remain in stock AddTile.
  CatchUp runs later and cannot infer exclusive ownership from that branch.
- `0xcf5805/0xcf5809` read grid+0x18 and float scale+0x34. Publication stores
  scaled unsigned-height minima/maxima at record+0x18/+0x1c at
  `0xcf58ad/0xcf58b4`, then increments the 32-bit version at `0xcf58bb`.
- `0x173e168` (`49 8b 7e 08`) passes self+8 as CTerrain in SysV RDI to
  publication. The existing alignment redirect remains the pass boundary.
  Save/Load/AddTile shims and their ABI checks are unchanged; their derivation
  is recorded in DEV_2B4FD093.

`SeenTerrains` retains four recent candidates. `FullTiles` copies headers,
records and vector descriptors via self `process_vm_readv`; inaccessible
memory produces a failed read. The selected candidate has the largest count
of full vectors. **This is a heuristic, not proof of world identity or
lifetime.** A freed allocation can remain readable, and successful guarded
reads do not pin it until the subsequent direct capture. The source comment
now describes a readable candidate rather than promising live ownership.

## Stream behavior and local corrections

The shared reader indexes complete records as the file grows. Native AddTile
refreshes missing entries; the load pass waits within the incoming policy's
bounds and catches up tiles, skipping only when all records have valid served
ranges. A partial stream still runs the complete native stock pass. The 1 ms
per tile estimate is inherited policy, not a Linux measurement from this job.

Keep valid record storage even if a later record in the same refresh is
malformed: upstream published indices before returning false without storing
their chunk. The shared fix retains the accepted prefix and closes the bad
stream. It applies to both platforms without changing the format.

Native PassDone disarms stream discovery after a completed load pass, and
LoadHook clears the old discovery flag even if the next save path cannot be
resolved. Otherwise a stream absent throughout loading could first appear
in play and overwrite terrain edits. Regression fixtures cover this case,
malformed suffix decoding, inaccessible candidates/grids/vector descriptors,
and the incoming growing/split stream and two-version behaviors.

## Live attempt and missing proof

Installed the final soldier candidate and merged Lua into cp -a backed-up
native actor payloads, with `terrain_sidecar=1`, `terrain_stream=1` and
`autoload=1`. The prescribed lab command exited 1 immediately:
`bwrap: setting up uid map: Permission denied`. No game process was created
for gdb. No menu, renderer/Vulkan device, world load, save, pass, CTerrain
lifetime or visible result was observed. No desktop input was sent.

Both actor payloads were restored; SHA-256 file and symlink manifests matched
the backups. Saves were untouched, no game remains and Steam was not changed.
`launch.txt`, `launch-result.txt`, `candidate.json`, `restoration.json`, and
copies of actor logs/data are in the job's `meta/live/`. Copied actor data and
older logs are historical, not observations of this candidate.

Still required: live saved-world identity across both terrain versions,
ownership and pager synchronization during pass-time CatchUp, and lifetime
between guarded selection and capture. Static evidence cannot establish
those contracts. Production enablement remains unported/unvalidated;
`terrain_sidecar=0` remains the compiled and shipped native default.
