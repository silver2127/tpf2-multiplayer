Windows target `f9d34252db190556a99423a813182e228a07e3a3` corrects the
previous inferred integer-vector reader to MSVC `std::vector<bool>`.
Its reported live Windows measurement is upstream evidence, not a local

## Static recheck

Read the lab's actual Steam build-35924 ELF. `readelf -n` confirms GNU
build-id `3a0e156390b0e6f1e372051c24802c8493ae454a`. Addresses below are
PIE RVAs, not absolute live addresses. Rechecked the earlier
[0047c19f investigation](DEV_0047C19F.md) with `objdump -d -M intel` and
Linux `funcsig.csv` exports:

- Registration `0x228b377` writes member offset `0x50` with bytes
  `48 c7 85 90 fc ff ff 50 00 00 00`; registration at `0x228b414` binds
  StopConfig to Stop. The StopConfig binding at `0x228b5b0` writes its
  maxLoad member offset `0x50` and calls `0x2285690` at `0x228b5cf`.
- Stop copy at `0xb83363..0xb83376` calculates the first bit count as
  `(endWord - beginWord) * 8 + endBit - beginBit`. Pointers are at
  Stop `+0x50/+0x60`, bit offsets at `+0x58/+0x68`, capacity end at `+0x70`.
  The second container uses `+0x78/+0x88`, bit offsets `+0x80/+0x90`,
  capacity end `+0x98`.
- The tail-copy loops at `0xb833d9..0xb8340f` and
  `0xb834d9..0xb8350f` test 64-bit words with a shifting one-bit mask;
  `83 f9 3f` compares the bit position to 63, then advances pointers by 8.
  Allocation at `0xb835c0..0xb835cb` rounds up by 63, shifts right 6,
  then left 3. These are two 40-byte libstdc++ bit vectors, not the
  Windows 32-byte vector-of-32-bit-words plus total-bit-count layout.
- `0xb83511/0xb83519` pass source/destination Stop `+0xa0` to the
  remaining vector copy at `0xad93e0`. The destructor `0xaa43f0` frees
  `+0xa0`, `+0x78`, `+0x50`, `+0x38`, `+0x10`; at `0xaa4459`,
  `48 81 c3 b8 00 00 00` advances by the Linux Stop stride `0xb8`.
  Windows offsets `+0x70/+0x90` must not be substituted here.
- Inspected StopConfig metatable setup `0x229a5a0..0x229c1d0` again.
  Exported signatures at `0x229a5a0` and `0x22763f0` describe load/unload
  getter properties taking `const StopConfig&`, setters taking
  `StopConfig&, const std::vector<int>&`, and a float maxLoad member.
  This investigation did not establish the complete getter conversion or
  whether modifying the returned Lua container writes back to native state.
- Rechecked UpdateLine `0x15f0050`: existing prologue bytes are
  `f3 0f 1e fa 55 48 89 e5 41 57 41 56 41 55`. The SysV arguments are
  return slot in rdi, engine in rsi, entity in edx, indirect Line in rcx
  (see [line ABI evidence](SLICE_LINES.md)). At `0x15f0080` it loads
  `[rcx]`, then zeros it at `0x15f0083`; the other stop-vector pointers
  are moved similarly. A future capture must read before that move.
  No runtime lifetime was observed in this job.

No new hook, offset-dependent native reader, or patch was installed. Existing
hook byte verification remains intact. Raw evidence is in this job's
`meta/live/{elf-notes,stop-copy,stop-destroy,stopconfig-registration,

## Live attempt and remaining proof

Installed this build's five native libraries and merged Lua into backed-up
native actor payloads. The prescribed lab launcher exited 1 immediately:
`bwrap: setting up uid map: Permission denied`. No game process existed for
a gdb attachment. No GPU, menu, loaded save, filter edit, or property
read-back was observed. No host policy or launcher bypass was attempted.
Both directories were restored; content manifests match their backups.
`meta/live/attempt.log`, `installed.json` and `restoration.json` record this.
Copied actor logs/data may predate this job and are not evidence of a live run.

Still needed: a loaded-save differential probe of load/unload flags against
Stop memory, including empty/all-zero values and word boundaries; proof of
capture lifetime at UpdateLine; actual Lua stopConfig replay/read-back.
In particular, `lineApplyCargo` currently appends through `sc.load` and
`sc.unload` property getters before assigning `s.stopConfig = sc`.
The table-based tests cannot establish persistence through native getters.
Windows' newly measured layout does not settle that Linux contract.

Decision: keep native capture unported and report PARTIAL. Shared wire tests
now use numeric flags, retain leading/trailing zeros and all-zero unload
lists, and exercise lengths 2, 30, 33, 65 and 1024. They exercise Lua capture
parsing, codec, replay builder and snapshot, not native packed-bit decoding.
