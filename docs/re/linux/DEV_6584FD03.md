ELF: native Steam 35924, GNU build-id

No Windows address or MSVC layout is reused.

## Static evidence

Windows walks four PE file-open imports. Linux `readelf -Wr` identifies
`fopen@GLIBC_2.2.5`, R_X86_64_JUMP_SLOT at `0x5a47730`. Its PLT slot
at `0x6dd160` is exactly:

```
ff 25 ca a5 36 05     jmp [rip+0x536a5ca]  # 0x5a47730
68 94 01 00 00        push 0x194
e9 a0 e6 ff ff        jmp 0x6db810
```

The slot is 16 bytes, including the complete lazy-binding tail. The next
PLT slot begins at +16. Instead of overwriting a loader-managed GOT value,
the native plugin byte-verifies this entire slot and replaces it with
`ff 25 00 00 00 00`, an eight-byte function pointer, and two NOPs. This
works before or after lazy binding and needs no relocated trampoline.
The existing host checks the build-id before initialization. Mismatch or
patch failure logs OFF; disabling `generator_memory` never verifies/writes
this site. `sites.json` and `verify_game.py` verify it against the real ELF.

Disassembly of `0x9855c0` identifies Lua's file loader by the `@%s` chunk-name
string at `0x3f1f7b9`, mode `r` at `0x3f1f7bd`, stdin alternative, BOM/shebang
skip, `0x1b` binary-signature branch, reader callback `0x9840c0`, load call
`0x983720`, ferror, and fclose. At `0x985639` it calls filename wrapper
`0x32064a0`; that wrapper normalizes/copies the filename through C++ strings,
then calls `fopen@plt` at `0x3206588`. It returns the FILE pointer untouched.
The loader stores that pointer at `[rbp-0x2048]`, passes its reader context
to the parser, then closes the stream at `0x9856e4`. Lua package path search
also calls the same wrapper at `0x9934ff` and closes at `0x99350c`.
The source generator is text, so the bytecode-only reopen path is irrelevant.
No libstdc++ object crosses the new hook boundary.

SysV ABI at the patched PLT: `rdi=const char* filename`, `rsi=const char* mode`,
`rax=FILE*` (null on failure). The detour is an ordinary C++ function with
that calling convention and is noexcept. Its own `std::fopen` goes through
the plugin's separate libc import; it never calls the replaced game PLT.
The returned anonymous `tmpfile` is owned by the engine and closed by the
verified caller, just like an ordinary opened FILE. Each open gets its own
stream, avoiding cache overwrite, filename collision and cache lifetime issues.

## Transformation and failure behavior

`generator_memory_text.h` shares the exact Windows transformation and Lua
optimizer, embedded by CMake on Linux and the original PowerShell build on
Windows. The anchor must occur once as a whole line; original line numbers
are preserved, and the optimizer is appended. A length-indexed scan also
avoids forming out-of-bounds pointers on very short inputs.

Linux matches the three exact, case-sensitive filenames beneath
`/res/config/terrain_generators/`. Writes/update opens, unrelated resources,
missing/repeated anchors, files over 4 MiB, read errors and temporary stream
failures fall through to libc opening the original file. Allocation failures
are contained and the source stream uses RAII. Original files are never
written. Maps of area <=32768*32768 retain the original pipeline.
