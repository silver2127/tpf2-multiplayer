# dev 61578d27: shared company-wash selectors

The incoming commit changes only the shared Lua stylesheet. No Windows hook,
address, ABI or struct change requires a new Linux counterpart. The selectors
are retained byte-for-byte. They still require an ancestor tagged !mpWinCoN;
the Linux slice does not apply that tag. Previous ownership/hook investigations
are in [DEV_5FB7AEA2.md](DEV_5FB7AEA2.md),
[DEV_DB8A4776.md](DEV_DB8A4776.md) and [DEV_8E31F1E0.md](DEV_8E31F1E0.md).

## Static follow-up / correction to previous missing evidence

Read the supplied ELF without executing it. `readelf -n` confirms build-id
`3a0e156390b0e6f1e372051c24802c8493ae454a`. Cross-checking the Linux menu
implementation found an existing style helper that the previous tint notes
had overlooked: `native/linux/src/menu_linux.cpp` uses 0x30550d0 for its
new button's class. Disassembled 0x30550d0..0x30551ff directly from the ELF.
These addresses are evidence only; no new patch is installed.

The menu caller and disassembly support SysV rdi=widget, rsi=mutable
libstdc++ string pointer. At 0x30550f2, `48 83 7e 08 00` checks string
length. At 0x3055126 (`48 8b b7 b8 00 00 00`) and 0x305512d
(`48 8b bf b0 00 00 00`) it loads the widget's range end/begin, then
calls 0xc3a520 and compares the result to the end. The insertion path
compares end with capacity at widget+0xc0, moves the source string into
the available slot and increments end by 0x20 at 0x3055195
(`48 83 83 b8 00 00 00 20`). It clears the source length/storage at
0x305519d..0x30551af. The full-capacity path calls the exported
std::vector<std::string>::_M_realloc_insert at 0xa0a930. Calls to
0x304f110 and 0x3054e10 follow insertion, before temporary-vector cleanup.
An exception landing pad begins at 0x30551f2.

This supplies native class append/layout evidence independently of the
Windows layout; the earlier blanket statement that no native style helper
was known is too broad. It does not establish a safe entity-window/HUD
relay, owner lookup, stale-class removal or lifetime across world changes.
Those contracts remain necessary before reusing it for company tinting.

Also rechecked 0x3129f10..0x3129f2e and 0x30518e0..0x305190f:
0x3129f20 (`e8 bb 79 f2 ff`) calls the latter; 0x30518f8
(`48 8d 7b 40`) selects widget+0x40, and 0x30518ff
(`e8 dc 72 98 fd`) calls std::string::_M_assign. This preserves the
previous distinction between the entity-ID setter and class mutation.

## Decision

Ship the shared selectors; keep native tint unavailable. No new native
implementation is required by this stylesheet-only diff, and it supplies
no additional ownership or hook-lifetime evidence to close the inherited
gap. No guessed patch or offset was introduced. The local game's res path
did not expose loose style_sheet files, so no claim of runtime selector
matching or rendered output is made. No game or Steam was launched.
