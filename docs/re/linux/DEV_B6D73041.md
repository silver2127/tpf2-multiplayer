# Free-commit threshold — dev b6d73041

Windows target: `b6d73041483deb189e879b08606027b27a7de57f`.

## Source comparison and native decision

Windows `terrain_compression.h::CommitTightBytes` now uses RAM/8 bounded to
2..4 GiB instead of 2..10 GiB; unknown RAM falls back to 4 GiB. A positive
`g_commitTightMB`, initialized from `commit_tight_mb`, overrides the automatic
threshold. Zero and negative values retain automatic behavior. Both terrain
and material workers consume this helper. The four incoming files are retained
exactly; no hooks, addresses, instruction bytes, layouts or ABI contracts change.

Reviewed native `memory_budget.h::TerrainTarget`, `terrain_pager.h::Policy`,
`Serve` and plugin configuration. The native policy samples MemAvailable once
per second, reserving RAM/7 bounded to 2..12 GiB with a RAM/4 cap bounded to
4..8 GiB. Its target is min(live, cap, max(0, resident + available - reserve)).
An explicit `terrain_cache_hot_mb` fixes the resident budget instead. There is
no commit-tight predicate or load throttle. The Windows change adjusts a
separate free-commit threshold, not that physical-memory reserve.

Retain the existing native adaptation established in
[dev 2b8505c7](DEV_2B8505C7.md) and [dev d8c98ccb](DEV_D8C98CCB.md).
Do not map this threshold onto MemAvailable or Committed_AS: the former is a
different resource and MADV_DONTNEED on the native mapped arena does not prove
a one-for-one Linux commit release. Document `commit_tight_mb` as Windows-only
rather than exposing an ineffective setting in the native configuration.
Inherited material/small-pager and Windows commit-controller differences remain.

## Validation scope

Added synthetic native policy cases for 94 GiB RAM: 33 GiB available permits
the 8 GiB cap; 12 GiB available preserves 8 GiB resident; 10 GiB available
reduces it to 6 GiB; 4 GiB available exhausts the resident target. These protect
the distinction between physical headroom and the changed Windows threshold,
and run before the fixture's userfaultfd availability check. They are not
measurements of the upstream machine or a game load.

The read-only verifier checked the actual lab ELF, Steam build 35924, GNU
build-id `3a0e156390b0e6f1e372051c24802c8493ae454a`, and all 39 guarded sites.
No new static engine contract or live ABI question is introduced by this
policy/configuration-only upstream change; no new disassembly or live probe
is needed. No game launch, load performance or cross-platform result is claimed.
