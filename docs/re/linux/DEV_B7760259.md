## Hot-join ordering: experimental implementation, default off

The incoming Windows history includes Linux research sources under
`docs/re/hotjoin/`. Their reported remote-lab results are upstream evidence,
not observations made during this integration. Adapted those sources into
`native/linux/src/order_canon_linux.{cpp,h}` and applied the accompanying
person-map sidecar change to the native implementation. Windows assembly and
MSVC code remain unchanged.

Independent checks used the actual lab ELF, `readelf -n`, full function
`objdump -d -M intel` dumps, and the function starts/sizes in
`~/tpf2-re/linux/functions.csv`. `tools/linux/verify_order_canon_elf.py`
checks the build-id, all 16 bytes at each site, the seven-byte steal boundaries,
and every direct branch/call in each enclosing function for interior targets.
All checks passed. Addresses are ELF virtual addresses plus the runtime PIE
base, not Windows RVAs transplanted to Linux.

are printed by the verifier and embedded in `kCanonSites`.

The cross-build anchor is the batch producer/consumer chain documented in
[HOTJOIN_ORDER](../HOTJOIN_ORDER.md), including the matching Windows sites
`927df6`, `a7c9fd`, `a59928`, `a867ce`, `21234de`. Fresh disassembly shows:

- Candidates: `15028b7` takes `rbp-90`; the loop reads 32-bit node entity IDs
  at `15028e6`, appends four bytes at a time, and every exit joins `1502918`
  before the output is populated. The copied vector owns its storage.
- Departures: `16f0b17/1f/2a` initialize the three pointers at `rbp-50/-48/-40`.
  `16f0b9d` reads the entity from the node, `16f0ba7` writes it into the batch,
  and the signal receives its address in SysV `rsi` at `16f0bd3`, with the
  signal call at `16f0bd8`.
- Arrivals: after the checked load/test, `16b5dd3` forms `rbp-a0`,
  `16b5dda` passes that plus `18` in `rsi` to the signal at `16b5dde`.
- Idle: the entry stores the incoming SysV system pointer in the frame slot;
  the checked instruction reloads it. The system-owned vector starts at +18.
- Capacity: `2e6e617` seeds MT with `0x1571` (5489). After the seed loop,
  `2e6e6c3` reloads the helper and `2e6e6ce` loads its +120 data block.
  Person apply is called at `2e6e75c`, followed by cargo processing. The
  incoming research specifies nine libstdc++ maps at 0x38-byte intervals,
  first node at +10, size at +18, node next at +0 and entity key at +8.
  Relinking preserves nodes/payloads but invalidates hash bucket predecessor
  pointers. **The claim that no later nested consumer needs those bucket
  pointers still needs local live proof.** No MSVC sentinel-ring offsets are
  used for these native maps.

The shim preserves GP registers, flags, XMM0–15, MXCSR and stack position,
aligns the stack for the SysV helper call, and replays the original seven
position-independent instruction bytes through a near trampoline. Fixtures
execute all five installed shims with both stack alignments, verify changed
instruction outputs as well as preserved registers, test every byte-guard
failure and every installation rollback (including the failed site), and
exercise malformed map counts/cycles. Empty vectors avoid null subtraction.

The existing five person-map traversal interceptors would override the new
physical order. Their sealed-owner sidecars now optionally sort by key, retain
the original capture records for validation and free sidecars with the verified
owner deleter. They activate only after the whole canonical module successfully
installs, so a rejected site cannot leave only the sidecar order active.

`TPF2MP_ORDER_CANON=1` explicitly opts into this experimental implementation;
otherwise no new game patch or sidecar behavior is enabled. This differs from
the upstream research default deliberately. Production ordering parity remains
unported pending live verification. Enabling only `tpf2mp_live_join.txt` is not
sufficient; do not use retained-world joins without validated matching sorts on
every peer. Frozen reloads also do not prove parity with Windows's new default
sorts.

## Title renderer and Steam transport

The native title dialog uses the existing SDL filter and software BGRA layer,
not new engine hooks. Join/create tabs, player/server/save paging, company
selection, mod-download modal, Tab/Shift+Tab/Escape, matched key releases and
covered-menu input capture use native UTF-8 strings and existing lobby actions.
The stored ZIP/TGA reader is adapted to `fopen`/`fseeko` and the configured game
path. It reads the game's preblurred title artwork at runtime, with a solid
fallback. Full-frame output uses both existing Vulkan and OpenGL presenters;
hover is composed into the title layer and does not require frame readback.
The in-world panel retains its existing layout. No artwork is redistributed.

The shared Steam tunnel retains Linux dlsym, four-byte callback packing,
socklen_t, nonblocking/CLOEXEC sockets, FD_SETSIZE checks and std::thread
lifecycle. New endpoint buffers are best effort; kernel limits are not changed.
Rate IDs 10/11 and buffer IDs 9/47 are tested through fake flat-C exports with
real loopback UDP. Bulk diagnostics use the existing packed session-state ABI.
No Steam client initialization is introduced.

## Local live attempt and evidence still needed

The native actor's library directory, Lua mod and entire userdata were backed
up as `.before-port`, then the soldier build and merged Lua were installed only
in the actor. Window settings were reduced to 1280x720. Standard lab launch
failed before game exec: `bwrap: setting up uid map: Permission denied`.
The fallback from DEV_D6DB920F retained every outer lab mount, used system
`/usr/bin/bwrap`, and bypassed nested pressure-vessel. RADV was requested via
`VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/radeon_icd.json`.

That attempt exited 53 at Steam initialization:
`SteamAPI_IsSteamRunning() did not locate a running instance of Steam`.
A /proc comm scan found no Steam or TransportFever process. Steam was neither
started nor modified. No title menu, selected GPU, loaded world, XTEST input,
or gdb attachment was reached. There is no local live ABI/lifetime or
cross-platform gameplay result to report.

contents and helper/map lifetimes through construction and destruction,
confirm no post-relink hash lookup and no active consumer of the idle list,

interval with people, vehicles, cargo, construction and later joins. The native
title dialog still needs an in-game visual/input check and real two-computer
