Target `65302e5d0eed83865488766003fb97e6e9768eea`, Linux Steam build 35924,

## Implementation and existing engine contract

The incoming native implementation is combined with the current Linux hook
publication gate, unsigned version increment, load-generation invalidation,
outward lookup and lookup counters. With `terrain_sidecar_decode_at_pass=1`,
AddTile still forwards to the original SysV function, records the CTerrain and
opens a pending local sidecar or stream, but does not look up or decode a tile.
The existing SettleStream/CatchUp path decodes at the load-sized alignment pass,
using up to 16 threads including the caller (additional workers only above 64
tiles). Each worker has its own DecodeScratch and claims distinct tile indices;
ApplyTile holds the shared file lock while decoding, range accounting is mutex
protected, and all workers join before publication and file release.

A terrain seen at AddTile has no range slot until its pass. Finished terrain
identities are therefore tracked separately; VersionPending includes seen but
unfinished terrains when deferral is enabled. The first completed version keeps
the file for the second. LoadHook resets identities and ranges for reused
addresses. Incomplete application runs the original alignment path. Small
passes and already-finished versions do not skip or decode again.

Unlike Windows, Linux sidecar installation already requires a byte-verified
alignment redirect regardless of `alignment_batch_tiles`. Do not copy the
Windows `alignmentBatch > 0 && alignmentSkipServed` requirement: there is no
native per-copy skip. Fixture tests prove deferral config defaults on inside
the opt-in sidecar path and may be disabled independently of batching.
`terrain_sidecar=0` remains the shipped native default.

No new hook, address, byte pattern, ABI or layout is introduced. The contracts
in [DEV_2B4FD093.md](DEV_2B4FD093.md) and
[DEV_26564158.md](DEV_26564158.md) remain in use. Fresh static verification of
the actual lab ELF passes all 39 guarded sites. Fresh disassembly confirms:

- AddTile `0xcf73f2`: `49 8b 77 18` reads terrain+0x18, the grid's nx is
  at +8, `48 8b 46 10` reads records at +0x10, and two LEAs produce the
  existing 40-byte record stride.
- Publication `0xcf5809`: `f3 0f 10 53 34` loads the terrain height scale.
  `0xcf58ad` / `0xcf58b4` store floats at record+0x18/+0x1c;
  `0xcf58bb` (`41 83 44 24 20 01`) increments record+0x20.
- Runtime guards and SysV AddTile/SaveGame/LoadGame forwarding are unchanged;
  partial hook installation remains forwarding-only until Enabled is published.

The Windows `profile_load.py --stack-at` addition uses dbghelp StackWalk64 and
PE unwind data; it is retained exactly as a Windows developer tool. Linux
investigation uses gdb's ELF unwinder (`thread apply all bt`, registers and
memory at verified sites), not Windows CONTEXT or PE addresses. No native
sampling profiler, nor equivalence of its sampling statistics, is claimed.

## Live attempt and evidence limits

The final code build was installed in backed-up native lab libraries/plugins
and Lua copies. The actor-only config enabled sidecars and deferred decoding,
set autoload=1 and disabled density rewriting. The prescribed launcher exited 1
immediately with `bwrap: setting up uid map: Permission denied`. No game reached
a menu, selected a Vulkan device or loaded terrain; there was no process for
gdb to inspect. No Steam restart, policy change, Proton launch or desktop input
was used. Payloads were restored and `diff -qr` matched both backups; no save
changed and no game remains running.

The prior live ownership/pager/lifetime gaps are still open, including proving
that no native consumer needs decoded heights between AddTile and the pass.
No timing or Windows performance claim is promoted to a Linux observation.
These are validation limits of the existing experimental sidecar path; no
part of this commit's runtime algorithm was omitted.

Evidence: `.git/port-65302e5-{build,lua,elf}.log`,
`.git/port-65302e5-{addtile,publication}.asm`, and the job's `meta/live/`
(launch result, restoration comparison, build/test logs and disassembly).
