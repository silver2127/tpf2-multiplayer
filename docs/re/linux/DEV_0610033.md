## Family inventory

The existing `Engine::GetNodeList` / AddFamily analysis in
[DEV_0115785C](DEV_0115785C.md) establishes the libstdc++ chain at engine+0x170,
count at +0x178, family pointer at chain node+0x10 and getter vslot 2.
The generator walks ELF relative relocations, anchors vtables on ecs Family
RTTI names, and reads each slot-2 implementation. Local verification finds
63 distinct getters: 28 with `f3 0f 1e fa 48 8d 47 08 c3` (family+8),
35 with `f3 0f 1e fa 31 c0 c3` (null). The complete table includes Town
0xa917d0 and TownBuilding 0xa917c0. Only PersonCapacity was recognized by the
previous list getter 0xa914c0. Install now verifies all 63 before patching;
unknown or interior addresses remain refused, and getters are never called.
The existing guarded sort and phmap index repair remain unchanged.

Local real-image fixture: maps PT_LOADs and applies RELATIVE relocations,
then constructs synthetic families using the actual image's vtables. It
observed `families=63/63 lists=28 reordered=28 moved=84 unknown/refused=0`.
All 35 no-list objects stayed untouched. It also counts exactly one list
covered by the old address. This executes mod code, not game code, and does
not establish loaded-game lifetimes or actual multiplayer determinism.

## Town trace sites and SysV ABI

The Linux function signature export anchors 0x14f5b80 to
`TownDeveloper::Develop(ecs::Engine&, ecs::Entity, bool,
boost::random::mt19937&, std::optional<float>, IProgressMonitor*) const`
and `Game/UrbanSim/TownDeveloper.cpp`. Its caller is TownSystem update
0x1746790, the already verified town-seed function.

Disassembly establishes:

- Entry saves RDI context at `[rbp-0xbf8]` (0x17467ae) and RSI engine at
  `[rbp-0xbe8]` (0x17467bc). Those slots are not rewritten before Develop.
- At 0x1746930..0x174698c the update reads context+8 -> vector begin,
  indexes with stride 8, and reads the entity from its first four bytes.
  The intervening division/multiplication computes `t%120 == (i%30)*4`.
- 0x1746825 constructs MT at rbp-0xa00; 0x1746847 saves its pointer at
  rbp-0xc58. The initializer writes 624 uint32 words and stores index 624
  as a qword at rbp-0x40 (0x174688c): exactly 2504 bytes including the index.
- At 0x17478d8..0x174791e, RDI = context+0x40 developer, RSI = engine,
  EDX = town from R13D, ECX = false, R8 = MT pointer, R9 = optional bits
  with its engagement byte cleared. The seventh argument, progress, is
  pushed as null. `e8 64 e2 da ff` at 0x1747917 calls 0x14f5b80.
- The installer verifies all 70 bytes from 0x17478d8 through the two pops
  after the call, plus build-id. A near stub redirects only the call's
  rel32 to the seven-argument SysV wrapper; original arguments pass through.
  TT hashes MT before/after the original call. TF comes after family sorts.
- Clock/context are captured by the existing seed trampoline, whose full
  339-byte entry/initializer guard is independently verified. The clock is
  recovered from the original native seed before Windows seed substitution.
  Boot now refuses trace installation if that seed hook failed, avoiding a
  trace without its clock/context source. Tracing stays opt-in.

`tools/linux/verify_town_trace_elf.py` reproduces these byte, instruction,
spill, vector and MT checks. Unit fixtures cover argument forwarding,
formatting, cadence, bad image/guard rejection and call redirection.
The real-image fixture also installs the trace against the actual ELF bytes.
