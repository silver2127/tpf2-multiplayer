# dev d3135a59: company permissions and foreign UI

Static analysis only of Steam Linux build 35924, GNU build-id
`3a0e156390b0e6f1e372051c24802c8493ae454a`. Addresses are ELF virtual
addresses relative to the loaded PIE. The game was never executed.

## Station permissions

The existing [StationFilter mapping](DEV_6CB03915.md#shared-stations) and its
SysV relay remain unchanged: edi=owner, esi=local player, eax=allow. The helper
now requires both companies mode and permission from `mp_company_perms.txt`.
The bounded parser matches Windows (256 player mappings, company IDs 1..255,
95-character codes, last matching mapping wins). Missing files, missing rules,
unknown players and the same company accept. `*` accepts, `-` rejects, and a
comma list accepts whole company IDs. A mutex protects a two-second cache.
The Lua LCREATE/LUPDATE checks use authoritative lockstep state after the UI
check, preserving the upstream treatment of permission races and existing lines.
No new game address, object offset or ABI is involved here.

## SHOW ALL ICONS

`xrefs.csv` source paths identify the ItemCreator.cpp region. The initialization
at `0x1383390` loads RTTI `0x5a01c18`, calls type lookup `0x9e3d50`, subtracts
one from the type slot and writes ItemCreatorImpl+0x190 at `0x13833af`.
The RTTI name is `N3ecs9component11PlayerOwnedE` (verified via `.rela.dyn`).

Visit is `0x13837d0` (1385 bytes in functions.csv): rdi points to the wrapper;
`[rdi]` is the implementation in rbx, esi is the entity value, saved at rbp-0x70.
Impl+0x28 is the ECS engine and +0x20 is the local player. At `0x13837fd`
it reads the cached PlayerOwned type. The presence bit test leads to
`0x1383b28`, calls slot lookup `0x9e5590`, selects contiguous or paged
four-byte components, and reads the owner. Missing/negative owners already
accept. The final comparison and backwards rejection branch are below.

The End body `0x138b9f0` (4381 bytes) walks the tree at impl+0x4b0, obtains
PlayerOwned using the same +0x190 type, and compares against impl+0x20.
GCC duplicated the comparison across paged and contiguous storage paths:
both must be opened. The accepted path resolves a position at `0x142a460`
and reads TransportVehicle using impl+0x1b0 (RTTI `0x5a03458`, name
`N3ecs9component16TransportVehicleE`, initialized at `0x13831d0..0x13831f5`).

HudIconManager::DoStep is anchored by its signature/source xrefs in
`0x1093b30`. It looks up PlayerOwned at `0x1093dee..0x1093e21`, storing the
type at rbp-0xec8. At `0x10941d5` it reads world+0x214 (local player), then
stores type/player in the context at rbp-0xe20 +8/+12 (`0x1094207` and
`0x10941ef`). The worker `0x1090ba0` (1963 bytes, also has DoStep signature
xrefs) loads this context from `[r15+8]` at `0x1090df0`: +8 is the type,
+12 the local player in r13d. Slot lookup and four-byte component addressing
lead to the owner equality at `0x1090cb2`. Equality jumps to the accepted
entity path; fallthrough advances to the next entity. This is the opposite
branch polarity from the Windows site's rejection branch.

| Linux site | Original | Replacement | Meaning |
|---|---|---|---|
| `0x1383b78` | `75 86` | `90 90` | Visit: do not reject foreign owner |
| `0x138ba6f` | `74 5e` | `eb 5e` | End paged: always jump to `0x138bacf` |
| `0x138bacd` | `75 a2` | `90 90` | End contiguous: do not skip |
| `0x1090cb5` | `0f 84 5d 01 00 00` | `e9 5e 01 00 00 90` | HUD: always jump to `0x1090e18` |

These edits introduce no calls or register clobbers. Compare instructions,
component reads, type/presence checks, and accepted-path register values stay
intact. `showicons=0` disables this group.

## Read-only foreign windows

The ViewCreator.cpp xrefs locate the view implementation region. RTTI name
`N2UI11ViewCreatorE` at `0x429a070` identifies the vtable whose typeinfo slot
is `0x59bc430`. The two Itanium destructor entries are `0x1465d20` and
`0x1465cc0`; the next slot, `0x59bc448`, is `0x1446c60`, CanCreateView
(1156 bytes). SysV arguments: rdi=ViewCreator, esi=entity value.

The function obtains world via `[this+8]+0x150`, the engine from world+0x28,
looks up PlayerOwned RTTI at `0x1446c9c` and resolves a four-byte component
with `0x9e5590`. At `0x1446d44` it reads the local player from world+0x214;
at `0x1446d52`, `39 11` compares `[rcx]` (owner) with edx (local).
The following `0f 85 b0 00 00 00` at **`0x1446d54`** jumps to the return
at `0x1446e0a` with eax=0. Replace only that six-byte branch with
`66 0f 1f 44 00 00`. Accepted entities continue through the existing Player
and entity-type predicates; no constructor or edit path is patched.
`foreignwindows=0` disables it.

Read-only behavior relies on the existing Linux native command cancellation
barrier plus upstream `CM.injForeignEdit`, now merged exactly. Supported
VSELL/VREV/VDEPOT/VLINE/LUPDATE captures reach the Lua owner filter. Existing
unsupported native edit categories remain blocked in multiplayer. This does
not add company-rename capture or widen command permissions.

## Runtime guards and tests

`company_ui_checks_linux.h` contains ten exact, complete instruction spans,
including comparisons, branch bytes, type initialization and argument/owner
loads. All guards for a feature are checked using SliceRead before mutation;
the existing slice initialization build-id gate applies. `ApplyUiPatches`
checks every original branch again, uses the existing readback-verifying
`Tpf2mpCodeWriteSelf`, and attempts rollback of the whole written prefix on a
write failure (logging any rollback failure). No trampoline is needed.

`verify_dev_d3135a59_elf.py` reads the actual ELF, verifies the build-id, all
ten spans, every original and replacement instruction, all five branch
destinations and whole-function instruction boundaries, lack of direct
branches into overwritten instruction interiors, PlayerOwned RTTI and the
ViewCreator vtable slot. The expanded movement CTest mutates guards and the
last branch to test refusal without earlier writes, then tests all replacements
in an anonymous fixture. It executes no game code. Existing SysV station relay
and new permission-file parsing cases also pass. Static/synthetic evidence
does not establish live UI rendering or multiplayer compatibility.

## Not ported: colour hooks, attempted mappings

The Windows icon and station-label relays and window-style detour were read
in full. Searches of Linux functions.csv/funcsig.csv did not supply named
AddVehicle/AddQuad/addStyleClass counterparts. Source/signature xrefs,
component initialization and fresh objdump disassembly were used instead.
The following are analysis leads, **not installed addresses**:

- Vehicle icon: inspected ItemCreator `0x1382000..0x138dce0`, including the
  four draw-helper calls at `0x138bcd8`, `0x138c08d`, `0x138c359`, `0x138c4dd`.
  The shared target `0x1385ec0` takes a flag in edx (`mov r15d,edx`), floats in
  XMM registers, and returns a packed rectangle in rax/rdx. Its nested
  `0x138612e -> 0x137cce0` is buffer selection, and `0x1386163 -> 0x1385d50`
  is vector growth. None establishes Windows AddQuad's nullable colour-pointer
  contract. A proven vehicle-only colour write/call and complete live register
  and entity flow for all carriers remain missing.
- Station label: tracing conditional colour selection found `cmove rsi,rcx`
  at `0x138952e`, choosing rbp-0x90/rbp-0x80; `0x1389549` moves it into rdx
  before `0x1389559 -> 0x1383570`. The subsequent click-rectangle registration
  at `0x1389579 -> 0x1381a70` uses the entity pointer from rbp-0xd0. This is a
  strong candidate for the Windows label background, but the draw callee's
  full colour-copy/lifetime contract and complete live-state preservation for
  an inserted helper were not established. No patch uses this candidate.
- Window wash: a call-frequency pass across `0x143ec40..0x1464000` found the
  13-call helper `0x1444ee0`. It takes rdi=widget and esi=entity, formats `%d`
  and prefixes `temp.view.entity_`, then calls `0x3129f10` at `0x1444f85` with
  a libstdc++ string. This identifies entity ID binding, not addStyleClass.
  Inspected the `addStyleClass` xref at `0x1cad7fd`: it is a Lua binding-table
  builder storing the method-name pointer, not a direct method call. Other
  name xrefs are in `0x1cb1250` and `0x1ce37d0`. A verified native style-class
  method, compatible string ownership/exception behavior, and safe owner
  lookup across world changes remain unresolved. Windows' cached render-engine
  pointer and MSVC string cannot be transplanted.

Consequently vehicle-icon tint, station-label background tint, and native
window wash remain off. The shared stylesheet is merged but the native class
assignment is absent. No native `iconcolor`/`windowcolor` implementation is
claimed. Analysis outputs are in `.git/{itemcreator,hudicons,hudstep,allviews,
drawcandidate,quadcandidate,stylebinding}.asm`; the addresses and reasoning
above persist independently of those disposable files.
