## 1. Executive summary

Decision: stations go strict on the SAME cancel path the road depot uses today (factory walk of the toAdd ConstructionEntity, arm by command pointer, cancel at CommandList::Add with the callback fired, CONXP inject, Lua ships CONX cancelled=1, every instance runs api.cmd.make.buildProposal at the stamp). No new command shape for placement. Module edits become strict with the same machinery plus one extra datum (toRemove[0]) and a replace-shaped replay (constructionsToRemove[1] + constructionsToAdd[1]) that mirrors the engine's own CreateProposalReplace, so the entity id is reused per instance and nothing ships an id.

Where the cancel path already stands (run 20260908-192711, the latest evidence): cancel_construction=1 with the LOSSY walker cancelled and replayed TWO UI placements of station/street/modular_terminal.con (each with 2 "value tag 1 unknown (depth 4)" omissions), both splitting the road (nodes=1 edges=2 rm=1), "EXEC CONX ... success=true" with EQUAL ent ids (194689, 132929) on a/b/c. So the cancel path is live for a road depot AND a street terminal, a lossy literal can replay fine, and the mid-road split is answered for a terminal. What it also shows is the reason this plan does not simply add station/ to the allowlist: the same run logs "STN: survivor-diff bulldozed town ASSET_GROUP 58629 at (-10011.9,678.8)" on every instance, 52 m from the terminal, a town asset a native placement would have left standing (section 2.2 item 4).

Reused unchanged: StashConxpFromProposal / SerLuaTable / SerLuaValue, the construction arm ("armed cancel: construction placement"), the Add hook (the "CANCEL local build" fired path), WriteInjectConxp, the CONXP inject parser, shipConxPair, execConX's cancelled gates (origin skip, cancelled-originator fallback, strict-bulldoze bypass, ctx.gatherBuildings=true).

Set cancel_construction=0 there NOW, before Milestone 1 is built. The walker still cancels after OMITTING every Variant tag it does not know (SerLuaValue returns false, the entry is rolled back, the walk still succeeds): the rail modular_station placed under this (runs/20260908-175043 seq=7) lost 17 booleans and asserted in GetSnapNodes on all three instances; the 192711 terminals lost 2 booleans each and replayed fine. ## 2. Where we are

### 2.1 The depot cancel path as it exists today

Factory hook, caller 0x419f62 (UI::ConstructionBuilder::MousePressed factory return; its CommandList::Add return is 0x419f81, which is what the "CANCEL local build (caller_rva=...)" line prints: the Add hook logs the Add return address, not the factory return), in the 0x419f62 branch of the factory hook:
- n/m/re/cet decoded from r8 (the construction_builder_util::Proposal) with DecodeNodes/DecodeEdges capped at 64 records each, silently; branch `m >= 1 && cet.ok` writes ROADC unconditionally (WriteInjectConRoad) and logs "shipping ROADC". The ROADC header carries ONE etype/stype/ttype taken from edge 0 (DecodeEdgeType decodes only edge 0).
- If cfg cancel_construction or conparams_dump: StashConxpFromProposal(r8). Arm only if stashed AND cancel_construction AND enabled AND suppress AND SessionLive(): g_pendingIsConx=1, g_pendingCmd=rcx, g_pendingNoCb=0 (the ConstructionBuilder waits on its callback), logged as "armed cancel: construction placement". Stash failure with cancel_construction logs "params not readable -- NOT cancelled, builds natively".
- `m >= 1 && !cet.ok` and `m == 0` ("free-standing, nothing to ship") never stash or arm.

StashConxpFromProposal: toAdd {begin,end} at r8+0x1f8/+0x200, only toAdd[0] walked; fileName = SSO string at CE+0x00; transf = 16 floats at CE+0x728; params = SerLuaTable(CE+0x460); fails on `!ok || o.trunc || nodes == 0`. Buffer g_conxpParams[8192]; CONXP_MAX_DEPTH 8 / CONXP_MAX_NODES 2048; Log() clips at 1200 bytes so the "[conxp] ... params(N node(s))=" line is truncated in the log while the stash is intact. The toRemove probe ("toRemove(r8+0x1e0) ...") is read-only.

Walker (SerLuaTable / SerLuaValue): key tags 2 (double) / 3 (string), anything else logged and skipped; value tags 2 / 3 / 4 (nested map); any other value tag logs "value tag %u unknown ... omitted" and returns false, the entry is rolled back and the table continues. Depth cap emits "{}" and returns true; the node cap ends the loop silently. ReadSsoString copies min(len, cap-1) and returns true, so a key over 255 bytes, a value over 1023 or a fileName over 511 ships silently truncated. None of these set o.trunc. This is the one place the never-cancel-on-a-failed-decode rule is not enforced.

Add hook: pointer identity `r8 == g_pendingCmd`; one-shot. Exits, as the code stands: (i) `!enabled` early return clears g_pendingCmd/NoCb/IsConx but NOT g_pendingHonour; (ii) NoCb==1 branch suppresses without firing and writes CONXP whenever g_pendingIsConx is set (so a stale construction stash could be emitted on a VEHICLE cancel); (iii) otherwise the callback impl is resolved through the _Getimpl slot at r9+0x38 (heap-stored functor), _Do_call read at vft+0x10 and fired under SEH. Fired: ZeroAddResult(rdx), "CANCEL local build (caller_rva=<Add return>), completion callback fired", WriteInjectConxp if IsConx. Not fired: if g_pendingHonour (set only by the vehicle factory arm) the branch "callback NOT fired but the cancel is ARMED -- honouring it" returns 1 WITHOUT writing CONXP and WITHOUT clearing g_pendingIsConx, so a stale IsConx=1 survives; else "construction cancel did not land -- CONXP dropped" and the build runs natively, the entity poll captures it as before. The construction arm neither clears Honour nor checks for a stale g_pendingCmd from the road/vehicle channels. Section 4.1 item 8 replaces this with one ResetPending().

Inject and wire: `CONXP <file> t=<16 x %.4f> params=<literal>`. Lua CONXP parser: w[3] must be `t=...`, params is the greedy tail `params=(.*)$`, pendingCons seated with name=escName(basename), cancelled=1, survivors = pre-build set. flushConPairs pairs with the ROADC within 150 m or ships CONP after 1.0 unit DROPPING cancelled/survivors. shipConxPair ships CONX with cost/bal nil when cancelled. No ARMED is written for constructions (WriteArmed's callers are all vehicle/road), so the solo gate `not peerSeen and (CM.lastArmed or 0) == 0` judges CONXP AND the ROADC written before it by a stale CM.lastArmed; the gate applies to every inject op except EVAL/HEAL/BUYTEST.

execConX: origin skip only when conx_strict is off and not cancelled (the code default is conx_strict TRUE); cancelled originator with a live native copy at the key falls back to strict replace; strict bulldoze phase bypassed when cancelled; ce.name = CM.depotName(...) with unescName(c.name) fallback when cancelled; both-new edges dropped as apron; ctx.gatherBuildings=true when cancelled; ignoreErrors = not selfRebuild; nil-ctx retry (which DROPS gatherBuildings); "make.buildProposal refused (...) -- falling back to buildConstruction" with seed stripped, no cancelled gate; first-attempt failure runs the footprint pre-clear and re-queues itself at gameTime()+1.5; originator failure "NOT rolling back", peer failure -> CONFAIL with failedSeq. execConFail rolls back the TARGET letter only. The success callback's survivor-diff bulldozes every non-owned CONSTRUCTION/ASSET_GROUP within 190 m that is not in the shipped list (keyed by e.position at %.1f, 3 m match), off the command queue; its ASSET_GROUP loop has no `id ~= bid` guard.

conxQueue timing: every gate uses LOCAL game time (queued-behind-busy `notBefore = nowB`, the strict re-queue +0.6, the failure retry +1.5, L* behind conx gameTime()); the pump pops when `nowG >= head.notBefore` and not conxBusy, and conxBusy is released by an async sendCommand callback that lands on a different frame per instance. Only the head of an empty queue applies at the stamp; a second construction in one interval, or any retry, applies at instance-local steps (memory: frame-tick-vs-sim-step determinism).

### 2.2 Exactly where a station differs

1. Params shape. The factory-time CE+0x460 table DOES carry `modules` for both families: runs/20260908-175043/native/tpf2_slice.log "[conxp] station/rail/modular_station/modular_station.con ... params(179 node(s))={["catenary"]=1,["length"]=2,["modules"]={[3400005]={...}" (16 numeric slot keys; inject line 3376 bytes), and runs/20260908-192711 "[conxp] station/street/modular_terminal.con ..." twice. Decompile agrees: UI::UpdateConstruction 0x41c3e0 writes params.modules[slotId] from the template before the constrFn runs (decomp_ce/UI_UpdateConstruction_params.c:283-287, tmpl/CR_modules_A.c:196-212); the constrFn wrapper assigns `construction.params = <input table>` (decomp_ce/ConstructionRep_Add_lambda.c:227-230); MakeProposalAdd copies it into CE+0x460 (linkage/MakeProposalAdd.c:183). The Variant is std::variant<lua::Nil, bool, double, std::string, lua::Table> (funcsig.csv rows for lua::Table::Put/Get), so tag 1 = bool. The omitted entries (17 in 175043, 2 per terminal in 192711) were all tag 1 at depth 4 (modules[slot].metadata) with payload low byte 01 and varying upper bytes (0000000b00000001, bee0000000000001, ffffffd5ffffff01, 40b751f333332901). Apply prunes modules whose slot was not built (decomp/applyProposal.c:2672 reads CE+0x460["modules"]), so post-apply ser(e.params) may legitimately be a SUBSET of the factory literal. CreateProposalReplace Puts `upgrade=true` (linkage/make_proposal_B.c:86-95) so the edit literal carries `upgrade`; whether the UI's in-place edit leaves it on the component is unmeasured (measurement M6).
2. Naming. CM.depotName produces "<Town> <Type> [#N]" from the .con basename; the engine names stations "<Town>", "<Town> East/North/Exchange/Branch", "Lower <Town>", "<Town> Port" (hybrid-era polled names across runs/). The engine computes the name on the originator at make time (MakeName 0xa182a0, called only from 0xa13e50 which passes it to MakeProposalAdd, linkage/make_proposal_C.c:39-46) and stores it in the CE at +0x8b0 (size +0x8c0, cap +0x8c8; decomp_ce/CE_ctor.c:33-35; read as the name at apply, decomp/applyProposal.c:1811-1817 via plVar43+0x116). The offset is decompile-confirmed; the CONTENT at factory time is unmeasured.
3. Child entities. Apply gives the construction Name only if ce.name is non-empty and PlayerOwned only if playerEntity >= 0 AND the name is non-empty (applyProposal.c:1816-1824); station children are named from ce.name per stations-list entry. Any non-empty ce.name is therefore safe for ownership; the exact string only matters cosmetically and for the STATION_GROUP name. A modular station can carry SEVERAL station children (rail + street terminal) and the group; today's post-build check reads co.depots[1] or co.stations[1] only, so a missing NAME/PLAYER_OWNED on child 2 or on the group (the click-crash class, minidumps 4057236f/59c3ba2e) passes. Lines resolve stops by group POSITION (lineSnapshot, buildLineObject, findStationGroupNear), never by id.
4. Footprint. The make-time toRemove vector is EMPTY for a placement. Correction to the context: the probe never printed the "EMPTY" branch; all placement probes printed "toRemove(r8+0x1e0) not a vector (rb=0 re=0)". A null begin/end IS an empty MSVC std::vector (the bulldoze read toRemove[0]=117434 from the same offset), so the conclusion stands via the misread branch. Footprint demolition therefore comes from Context.gatherBuildings=true on every instance. The survivor-diff is NOT a no-op on top of that: 183815 bulldozed town ASSET_GROUP 116382 and 63487 on all three boxes, 192711 bulldozed ASSET_GROUP 58629 52 m from the terminal ("37 survivor(s) shipped, 1 kept in 190 m disk, 1 removed"). Anything present after apply but absent or moved in the pre-build snapshot is demolished, off the command queue (so sim persons die at different sim-times per instance, the n: lane), and neither egeo (edges) nor the c-lane (constructions) can see it. Deterministic only while the window content is identical everywhere; a town building spawned on the step between capture and callback is a one-sided bulldoze. Section 4.2 item 6 skips it under cancelled=1.
5. Street payload. A modular rail station arrives as 25 track nodes / 24 track edges / 0 removals for ONE track with 4 modules; all edges are both-new and dropped as apron, so the replay is CE-only (nodes=0 edges=0) and the .con regenerates the platform network. A 3-track station overflows the 64-record cap with no log; a street entrance snapped to an EXISTING road node (positive id, survives the apron filter) would be replayed with edge 0's type (TRACK) on every instance because the ROADC header has one type. A terminal arrives as 1 node / 2 edges / 1 removal and replays as a road split (192711). A missing node in spos/idmap is a silent skip on a peer.
6. Free-standing. Harbours, shipyards, airports and off-road depots take the `m == 0` branch: no ROADC, no stash, no arm; the poll ships CONP; execute() routes CONP into execConX, execConP is dead code. They are NOT "deliberately native" today: with the code default conx_strict TRUE the originator does not take the origin skip, it enters the strict bulldoze+rebuild branch (needing a consByKey rec that id reuse over buildings can miss, item 10) and rebuilds at +0.6 with ignoreErrors=false; an unrecoverable "NOT rolling back" leaves the construction on peers only. Never measured for an airport footprint. Section 4.2 item 10 and Milestone 3 address this.
7. z/height. Hybrid stations desynced by 0.1 m in z (host native vs peer buildProposal). Under cancelled=1 all instances run the same scripted build; whether THAT build is deterministic across instances for a station is what dump_egeo measures (measurement M8). The c-lane hash excludes z.
8. Replay failure symmetry. In 175043 seq=7 all three instances failed (GetSnapNodes `it->second.second == 1`, make_proposal.cpp:606; the string is referenced from a17eb0/417410/a16d00, all make-time, and the sol2 buildProposal failed at make, 4 lines per box) so nothing diverged. Because the 192711 terminals replayed with lossy literals, the assert is more likely a SHAPE question (the CE-only rail proposal with the platform-track network regenerated by the .con, or gatherBuildings=true over a rail footprint) than a fidelity question; it stays open until the measurement M8 control run with gatherBuildings=false. Rollback today is asymmetric in three ways: the originator does not roll back at all, CONFAIL is target-letter-only (peer b fails, peer c succeeds: a and b have no station, c keeps it), and the cancelled fallback to buildConstruction runs on every instance and can succeed on some and fail on others (175043 only avoided this because the fallback failed too; a partial success is undetected).
9. Edits. The originator's UI module edit changes params in place (same id) and is captured by scanConstructionEdits every 30 ticks -> CONU; peers call game.interface.upgradeConstruction with seed stripped (execConU). Run 183206 shows two real bugs: (a) scanConstructionEdits, pollNewConstructions, findConstructionForRoadc AND primeConstructions compute `pstr = (e and e.params) and ser(e.params) or "{}"` so a nil getEntity shipped `params={}` CONU lines that upgradeConstruction on the peers accepted with EMPTY params (and a save-game station primed as "{}" makes the first scan ship a spurious full-params CONU on load); (b) execConU's alive check passed on 117434 after the player had natively bulldozed it, and the upgrade hit the nil-entity GetComponentDataIndex assert (minidump). CM.constructionAt returns the FIRST player construction in getEntities order within 6 m, no file check, no nearest tie-break.
10. Entity id reuse blinds the replay poll. pollNewConstructions only looks at ids not in knownCons, knownCons is never pruned, and Apply hands toAdd[0] the first toRemove entity (applyProposal.c:1806). With gatherBuildings=true a station over town buildings takes a demolished CONSTRUCTION's id on all three instances -> the "replayed landed" branch never runs, consByKey has no record, expectedCons[key] stays set forever (the pollConstructionRemovals tripwire then blocks a real demolish), and later module edits/demolishes of that station are never captured. 183815 seq2 landed as ent=116382, the id of an ASSET_GROUP bulldozed seconds earlier (registered only because ASSET_GROUP ids are not in knownCons). SLICE_STATUS documents the same reuse for the hybrid capture; the replay side has no rescue. Section 4.2 item 11.

6. No rollback op for an edit is designed; the acceptance bar is 0 CONUXFAIL over the Milestone 5 test set.

Entity id continuity: Apply pushes every toRemove construction into constructionEntitiesToReuse and toAdd[i] takes reuse[i] (applyProposal.c:1263 assert text, :1806 pop), fresh entities only when toAdd > toRemove. With primitive A the LOCAL id is reused on each instance exactly as a UI edit does, consByKey stays valid and pollConstructionRemovals sees the entity alive throughout. With primitive B the id may change (re-measured by M6): pollNewConstructions' expectedEdit branch adopts it and the tripwire blocks a false DEMOLISH, bounded by the flag expiry.
